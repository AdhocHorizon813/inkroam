# 内容高度与接光面

2026-10-06，用户授权在层次感中加入内容卡片相对背景的高度。此项是空间关系试验，不是导航性能优化；不修改已确认的导航本体受光、宽度或过渡曲线。

## 实现

DepthReceivers.vue在主站和错误页的导航之后挂载一个固定的、不可交互、辅助技术隐藏的SVG绘制层。SSR不输出该层；仅现代模式轻柔/鲜明启用。没有可用观察器时保留旧CSS投影。

测量导航及顶级hero/latest-section/manifesto/standard-page/article-page的实际矩形与圆角。两张互补遮罩按这些形状划分接光区域：

- 内容范围接收近投影：偏移8px、模糊10px，采用既有导航投光颜色。
- 背景范围接收远投影：偏移28px、模糊24px，强度为近投影的55%。内容范围完全裁除这层，避免同一处两层完整叠亮。
- 手机缩短为近6px/8px、远22px/18px。
- 导航自身范围从两张遮罩中剔除，玻璃内部受光继续由原CSS绘制。
- 两层沿用原320ms展开/520ms收起透明度过渡和scrolled的.58强度，不动画模糊值。

这些blur是CSS filter blur的参数，不是与CSS box-shadow blur数值等效的物理距离。

内容卡片向背景投的影**已从 SVG 接光层搬到 `depth.css` 的静态 `box-shadow`**（2026-10-06，用户判定 SVG 实现方式不可行）。四组值：深色 轻柔 `0 3px 8px -2px rgb(0 0 0/.16)` + `0 14px 28px -6px /.30`、鲜明 `4/10/-2 /.20` + `20/40/-10 /.40`；浅色 轻柔 `rgb(20 24 30/.07)` + `/.14`、鲜明 `/.09` + `/.20`，作用在 `.hero/.latest-section/.manifesto/.standard-page/.article-page` 上。**为什么搬**：旧实现用固定 SVG 层，必须在每次滚动重测每张卡片，于是拖影（测→rAF→重渲染差一帧）、卡顿（每帧重渲大模糊遮罩）、闪回（卡片滑出视口被判空 → 整层卸载并回退旧光条）三样全占；阴影是静态几何，挂在卡片上就跟着卡片合成平移、零 JS、永不卸载。代价：本规则接管这些表面的 box-shadow 栈，材质自带的 `--surface-shadow` 不再叠加（规则里保留了一层贴近的环境影）。`check-depth` 的两条不变量相应放宽：读面只允许静态 box-shadow（其他光学仍禁止）、阴影只允许出现在导航装饰与静态卡片影上。

有有效接光几何后标记html[data-depth-receivers=true]，仅把旧导航伪元素的外部光条颜色置透明，交由近/远两层替代；内部均匀受光和顶部高光保持。关闭、纸媒或缺乏有效几何时移除标记，旧CSS回退恢复。

## 边界与限制（不能当成已验收）

- 本轮区分的是导航**表面整体光/影**的接收距离；导航文字、搜索图标、彩色标识的既有细节投影仍保留原行为，没有复制字形或把它们逐个重建到SVG中。
- 遮挡按圆角表面的几何范围处理，暂不根据玻璃透明度计算远光透射；不冒称真实光学、真实高度或逐像素材质识别。
- 近投影以低强度绘制在内容表面上，可能影响顶端内容对比度；需要视觉检查。卡片范围外的阴影和近/远光也可能需要调强度，但不要通过重新装修导航解决。
- 目前按统一圆角矩形建模，读取左上角半径；不支持不同角半径/非矩形内容面。
- 位于首层正常文档流的内容卡片受支持；顶层弹窗、下拉框沿用原层级，不成为接光面。
- 不新增持续动画循环。启用时共享onPageScroll入口，用一次rAF合并测量；ResizeObserver处理导航变宽与内容尺寸变化。关闭后卸载滚动/resize监听及ResizeObserver，仅保留设置属性观察；卸载时全部清理。
- 长讲义几何在视口外96px处裁切，避免为数万像素长的文章创建巨大模糊表面；不能裁到可见顶边，否则会凭空出现一道阴影。
- 无JS时不启用接光层；专注模式隐藏导航后没有导航投光，卡片自身高度提示仍可保留。
- 新增了测量与绘制成本，没有性能录制，不宣称解决此前宽度+明暗卡顿问题。

## 检查与交接

### 全页模糊回归修复

用户实机发现全页模糊。原因不是预期的表面接光，而是Vue scoped编译把`:global(:root[...]) .depth-receivers__elevation`编译成裸`:root[...]`，导致html被施加18px模糊和14px位移；滚动态透明度同样逃逸。已将完整后代选择器放进`:global(...)`，回归测试实际编译SFC样式、解析产物，禁止投影规则作用于页面根节点。修复后普通检查32/32和静态构建通过，未用浏览器验收。此前检查通过不代表已验证视觉正确。

本轮typecheck、32/32普通检查、/inkroam/静态生成、35/35产物门禁、git diff --check均通过。日志在tmp/depth-receivers-*。没有浏览器或GPU性能验收，未提交部署。

`scripts/check-depth-receivers.mjs`检查几何有效性、长文边界、开启/关闭/卸载监听、滚动合帧、路由重测、隐藏导航回退以及源码遮罩契约；纳入npm run check。该测试不是浏览器像素验收。

用户当前要求不使用浏览器自动化。之后人工检查：首页多个卡片、长文章滚动、浅色/深色、关闭/两档、手机、专注模式。重点看卡片边缘是否有拼接、遮罩对齐、是否盖到内容、滚动位置是否稳定。
