2026-10-06 补充：[内容高度与近/远接光面](depth-receivers.md)。仅开启层次感时将导航整体外投影按内容/背景划分，并为内容表面补充离地阴影；导航本体配方和过渡保留。具体限制、性能成本与验证状态以该文和最新断点为准。

更新：2026-10-05。以此文和当前代码为准，旧的整片导航光场、多层追加黑影已撤下。

## 边界与偏好

- 关闭 / 轻柔 / 鲜明；默认关闭，沿用v5存储，独立于默认设置；恢复默认时关闭。
- 所有新增规则匹配modern与soft/defined。关闭与纸媒不命中，原main.css未修改。
- 深色下导航玻璃与内部元素允许略微自发光（2026-10-05 用户授权，取代旧的“深色玻璃绝不发光”）：只用贴轮廓外发光与零偏移光晕，不做面内填充、不做整片光带，不能成为灯板。正文、公式、代码仍不作为光源。
- 不新增依赖、DOM副本、Canvas、事件监听或逐帧动画。
- [Apple材质分层原则](https://developer.apple.com/videos/play/wwdc2025/219/)仅为方向参考。元素投光是用户提出的CSS试验，不是真实折射、遮挡计算或原生Liquid Glass。

## 当前元素级实现

代码位于app/assets/css/depth.css，在main.css之后加载。

| 元素 | 实现 | 深色 | 浅色 |
| --- | --- | --- | --- |
| 站点名称、导航文字 | 两层向下偏移的text-shadow，取currentColor | 按实际字形投出衰减微光 | 深色字形造成微弱遮挡影 |
| 搜索图标 | 仅16px图标使用一次drop-shadow | 按SVG透明轮廓投光 | 同轮廓遮挡影 |
| 彩色站点标识 | 独立::after的矩形box-shadow，继承圆角和主题色 | 彩色元素向下投光 | 半透彩色玻璃对上方光染色、衰减后透到下方 |
| 导航玻璃 | 透明::after外投影，原材质阴影保留 | 冷白漫射 + 两层贴轮廓外发光，玻璃自身像在微微发光 | 极弱遮挡影，不发光，不再叠加导航细亮边 |

投影与元素一起跟随sticky导航，内容从其下经过。不移动真实文字或点击区域；只有导航overflow改为visible，让投影能落到其下方。站点标识增加position:relative定位装饰，不改变正常流尺寸。投影是绘制效果，不产生新的可点击区域；标识装饰pointer-events:none。

原有导航和标识阴影没有被替换。玻璃的光影只画在透明装饰伪元素上：向下 0 14px 30px -12px，深色另叠两层零偏移外发光 0 0 24px 与 0 0 60px -12px（浅色RGB24/30/40，深色RGB220/230/248、226/234/250）。没有面内填充，所以导航文字对比度不受影响。元素投光缩短、变柔，降低第二排模糊字形的风险。

文字颜色本身的透明度还会参与最终混色，表中不是最终像素亮度。标识矩形投影spread为-3px，模糊取远处blur；不会照亮整个导航宽度。2026-10-05 只动了两处：①导航栏向外投的那道影的 alpha（深浅各约 +18%），元素投影的比例、Y/blur、手机规则一律保持原值；②深色自发光，全部是零偏移光晕（字形8px、图标6px、标识14px），只贴轮廓、不填充面内。

深色自发光的分层（2026-10-05 第四轮反馈后定稿）：只保留三层——贴轮廓弱外发光 0 0 14px、玻璃面内部受光 inset 0 0 12px 200px（**整面均匀**：无上下偏移，扩散 200px 远超盒面，所以整块玻璃一起亮，而不是顶部一道亮带）、向下投的那道影 0 14px 30px -12px。用户明确点出这里的差别：**上重下轻＝伪高光**，等于用方向性渐变冒充光源；面自身发光必须是无方向的整面光。此前的两种做法都已被否：只锁在上下边沿（-16px 扩散）与上重下轻渐变。**54px 宽衰减层已删除**：它太弱，各层落进同一批 8bit 色阶格子，平台边缘的 1/255 台阶就是用户看到的横带；层数越少、梯度越陡，横带越不明显。贴轮廓外发光定在 .07/.10 保持边缘减量，内部受光 .12/.16；向下那道影经两轮加强提到 **.20/.30**（用户原话：“向下投射的光条太弱，配不上现在的自发光”“还是太弱”），并把光条几何拆成独立 token —— 深色 0 18px 48px -6px、浅色仍是 0 14px 30px -12px（浅色不动）。原因是原先共用 `-12px` 负扩散，把光挤在底边十几像素内，光条根本铺不开；只加 alpha 也救不回来。check-depth 的不变量：深色光条 alpha 必须 ≥ 内部受光，浅色遮挡影必须弱于深色光条，且光条几何必须走 --depth-glass-band-*。浅色随后也按其本来机制加强（用户：“浅色的强度也有点不够”）：.065/.095 → **.11/.15**，几何 14/30/-12px → **16/40/-8px**；浅色不引入任何发光 token，仍然只是遮挡影，且刻意保持弱于深色的光条以便两档区分。用户接着说“看不清浅色的彩色玻璃效果”，于是单独提高彩标的彩色透光比例：浅色 `--depth-project-tint` 8%/12% → **18%/26%**（深色标识彩光 14%/20% 不动，彩标那层几何 0 26/30px 16/20px -3px 不动）。check-depth 新增不变量：浅色彩色透光不得低于 15%，也就是不许再退回发丝级。深色元素向下投射同步上调：近/远 14%/5%（轻柔）、22%/7%（鲜明），标识彩光 14%/20%；浅色投影维持 6/2、10/3 与 8%/12% 不变。实测依据（**只读正中一列像素 x=153，不做行平均、不做平滑**；脚本 tmp/analyze-glow-bands.mjs 的 center 模式，复用 tmp/png-diff.mjs 的解码器）：玻璃体 y=0–26 恒为 RGB(18,35,57)、亮度 33.0，y=27–39 恒为 RGB(19,35,57)、亮度 33.2 —— 玻璃面自身是一条平线，光全落在 1px 边框线上（最亮行 y=42：RGB(70,83,99)、亮度 81.4）。y=42 往下亮度 48.9→34.6 衰减，但**方向反转 8 次**：亮带依次 81.4 → 48.9 → 38.5(y=61) → 36.5(y=68) → 34.9(y=83)，相邻级只差 0.1–0.7/255。用户看到的“白黑白黑、白色递减”成立；成因是多个极弱图层叠加后落进同一批 8bit 量化格子，平台被 1/255 台阶隔开，肉眼把台阶看成横条纹，不是真实光源。上一版用中间 70% 行平均得出“没有第二条亮带”，该口径已作废，不要再拿来下结论。

根据第二份评价（`tmp/inkroam-dark-navbar-material-tuning.md` 第 2 节），玻璃 ::after 另加一条极弱纵向材质渐变 `linear-gradient(180deg, rgb(255 255 255 / .025) 0%, rgb(255 255 255 / .008) 46%, rgb(0 0 0 / .012) 100%)`，用来打散“大面积均匀深色 = 磨砂亚克力板”的观感；三个 alpha 都在 3% 以内，属于材质，不是方向性光照。注意它与用户先前“面内要全部均匀”的口径相抵触，尚未经用户视觉验收；要回到完全均匀只需删掉这一条 `background`（`scripts/check-depth.mjs` 会随之跳过 ≤3% 渐变检查，其余不变量不受影响）。

Scrolled 状态（第三份评价 `tmp/inkroam-dark-navbar-scrolled-layer-tuning.md`，2026-10-05）：Navbar 滚动后横向展开到近满屏，同一套光学强度会被放大成横贯视口的光带，因此“面越大单位面积光效越弱”。**过渡必须保留，但不能靠插值大模糊阴影**——首版逐帧插值三层 box-shadow（200px 内扩散 + 48px 模糊）与 background 渐变，用户实测“动画太卡了”，等于整屏重绘。定为整片装饰的 compositor 友好淡出，且**两个方向非对称**：展开方向由 scrolled 规则管 `[data-scrolled='true'] .site-header::after { opacity: .58; transition: opacity 320ms cubic-bezier(.22, .8, .3, 1); }`（前沿但比 `--ease-fluid` 温和，让变暗领先变宽）；收起方向由基础规则管 `.site-header::after { transition: opacity 520ms cubic-bezier(.4, 0, .2, 1); }`（更慢更平滑，条先收窄、光再慢慢升回，避免弹回）。opacity .58 与逐项衰减的比值相当（光条 ×.55、整面受光 ×.62、顶部高光 ×.58），层数、几何、token 一律不动；踩过的坑：`box-shadow/background` 过渡会逐帧整屏重绘（卡顿），`--ease-fluid` 前 16% 就走完约 95%（突变感）。depth.css 里现有三处过渡且都是 opacity：面板 1px 反光 180ms、展开 320ms、收起 520ms；`prefers-reduced-motion` 下都为 none。

最终 A/B（`tmp/deepseek-dark-navbar-scrolled-final-ab.md`，2026-10-05）：只把 Scrolled 的**外部环境光**再降约 15%（B 版）——覆盖 `--depth-glass-light`：深色 .20→.17、.30→.26，浅色 .11→.095、.15→.13；面内受光、顶部高光、光条几何/blur、整体 scrolled 淡出与 main.css 均不动，因此 bar 本体亮度不变。A = 删掉那四个 `[data-scrolled='true']` + `--depth-glass-light` 的 token 块。该建议明确要求由用户肉眼判定：**用户已判定采用 B**；按该建议，Rest + Scrolled 一起冻结为 Navbar Reference，不再进入 0.018/0.020 式的无限微调。

仅外观面板保留1px中空反光：opacity .24/.42；按压/键盘焦点增加 .08，过渡180ms，减少动态效果时无过渡。导航两种明暗均不使用此反光，避免与新面层线索叠成塑料亮框。下拉背景局部反光浅色 .035/.065、深色 .025/.045。

## 与真实光学的区别

- text-shadow保留字形，drop-shadow保留图标轮廓，不读取或复制DOM文字；但投影不会随距离做透视变形。
- 彩色标识使用既有主题色，而非动态取色或真实透射率计算；当前只覆盖这个明确的彩色元素，不自动扫描全站。
- 光直接合成在下方画面上，不识别内容/背景材质、实际遮挡或表面高度。
- 没有新增全尺寸滤镜或backdrop-filter；图标的小滤镜和阴影仍有绘制成本，未进行GPU测量。
- 不新增持续动效；保持已有主题/外观切换机制。
