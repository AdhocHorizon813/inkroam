# 导航与卡片投影的纯 CSS 逼近（方案 B）：实现方法与损失

> 历史提案，未实施。下文性能成本公式、像素误差、一次栅格化和“不再重绘”等描述均为待验证的估计或预期，不是浏览器实测保证；“无解”只限于这里比较的方案，不能推广为所有 CSS 技术的不可能性证明。原实现的缓存与裁剪后来已调整，当前状态以 [接光层记录](depth-receivers.md) 和 [2026-10-07 实测](depth-browser-comparison-2026-10-07.md) 为准。

2026-10-06。本文只讨论**方案 B**：把接光层（`DepthReceivers.vue`）承担的"导航投影"整体搬回纯 CSS。它是**计划**，尚未实现；当前代码里卡片影已是不依赖 SVG 的静态 `box-shadow`（见 `docs/depth-receivers.md`），导航投影仍在 SVG 层里。**导航本体配方（B 档参数、`--depth-glass-*`、320/520ms 非对称过渡）在方案 B 中一律不动。**

## 1. 为什么要换（动机）

现实现是"固定 SVG 层 + 每次滚动重测每张卡片"，实测症状与成本：

```text
拖影   ：测量 → rAF → Vue 重渲染，差一帧，影子落在卡片后面
卡顿   ：每帧重渲"每卡一矩形 + 两层大模糊遮罩"；远投影 blur 作用在视口大小矩形上
闪回   ：surfaces 为空时整层 v-if 卸载、data-depth-receivers 删除、旧 CSS 光带回退，来回闪
GPU 成本：成本 ∝ 被模糊像素数 × σ × 帧数；桌面 1180+px、DPR2，远大于手机视口
```

## 2. 参照模型（验收基准，必须写死）

同一光源（导航矩形 W×H、圆角 r），按**接光面**分两档：

| 层 | 落点 | SVG 参数 | 裁剪 |
| --- | --- | --- | --- |
| 近 | 内容卡片 | σ=10px、下移 +8px、填充 α | 只保留卡片范围 |
| 远 | 页面背景 | σ=24px、下移 +28px、填充 α、整体 opacity .55 | 全屏 − 卡片 − 导航 |

手机：近 σ8/+6、远 σ18/+22。滚动态两层同乘 `.58`；过渡**只动 opacity**，展开 320ms `cubic-bezier(.22,.8,.3,1)`、收起 520ms `cubic-bezier(.4,0,.2,1)`。深浅色是**颜色交换**（浅色=深灰遮挡影，深色=冷白投光），不是 alpha 变化。

**换算 ①（最容易错的一条）**：SVG `filter: blur(x)` 的 x 即高斯 σ；CSS `box-shadow` 的 blur 半径 ≈ **2σ**，位移与 SVG 相同，spread 取 0。

| | SVG | CSS 等价 |
| --- | --- | --- |
| 近 | σ10 / +8 / α | `inset 0 8px 20px 0 color(α)` |
| 远 | σ24 / +28 / α×.55 | `0 28px 48px 0 color(α×.55)` |

## 3. 方案 B 的架构（按接收方分层，而不是按发射源）

```text
① 远层：画在"背景接收层"上的一条固定顶部渐变带
   - 几何是常量（导航 top/宽度在断点内固定），零 JS、零滤镜、零遮罩
   - 用 5~6 个色标近似高斯尾部，比 box-shadow 更可控（可单独压尾部，避免 8bit 台阶）
② 近层：卡片自己的 inset 顶光，挂在读面（.hero/.latest-section/.manifesto/.standard-page/.article-page）
   - 静态、随卡片合成平移、只覆盖卡片顶部，不需要任何模糊滤镜
③ 导航：只保留材质阴影 + 滚动态 opacity 淡出（本方案不碰）
```

远层色标示例（α 为模式底色，深色 `rgb(226 234 250)`、浅色 `rgb(24 30 40)`；数值按 σ24 近似，需要像素比对后再定稿）：

```text
0px  α×.55     8px  α×.50    20px α×.40    34px α×.27    52px α×.14    74px α×.06    96px α×0
```

近似公式（高斯尾部，σ=24，峰值取 .55）：`α(d) ≈ .55·α·exp(-d²/(2σ²))`，再按 8bit 取整成色标。

## 4. 损失清单（本方案真正的代价）

### L1 轮廓 → 边缘梯度（轻微，可接受）
SVG 近层是"导航矩形的模糊剪影"（含圆角与横向两端衰减）；CSS inset 是沿边锚定的梯度，横向均匀。
- 影响：只在导航两端圆角处，静止态导航与卡片同为 shell 宽（≈1120px）时预计 **<1–2/255**。
- 前提：**只对与 shell 同宽的顶级读面成立**。将来若出现窄卡片、居中卡片或不同圆角，差异会放大，需要按卡片单独定值。

### L2 近/远在交界处的强度台阶（中，需要补偿）
参照模型用同一层光穿过接收面，交界处连续；B 是两处独立绘制，**卡片与背景交界会出现一阶不连续**。
- 两条抹平路径：
  (a) 远层在卡片横向范围内不画（把渐变带做成"两侧亮、中间弱"）→ 交界仍有一档，但方向正确；
  (b) 近层顶部值取"近 + 远在该处的贡献"，让总和与参照对齐（推荐）。
- 残留误差：预计 **±2–4/255**，在 aurora/art 这类高对比背景上最明显。

### L3 失去"随几何自动跟随"（中高，维护风险）
SVG 每次测量自动对齐；B 的远层渐变几何是**写死的常量**。
- 导航 `top` 在断点间不同（18px / 10px / 7px…），必须每个断点各写一份；导航高度、shell 宽度变化同样要人工同步。
- 缓解：把导航 top 抽成 `--nav-top` 变量，由现有规则同步（仍需人工维护，不会自动感知）。

### L4 贴近导航时的叠加（中）
卡片顶边**紧贴**导航下沿时，卡片 inset 与导航投影落在同一条边，会叠亮/叠暗。
- 缓解：inset 顶部留 1px 缓冲或按 `.58` 同步淡出；无法用 CSS 感知"贴边"状态，属于接受范围内的近似。

### L5 过渡错拍（必须处理，否则是缺陷）
参照模型两层共用一套 `.58` + 320/520ms；B 里远层渐变与卡片 inset 是两处，若不一起过渡会出现"卡片先淡、背景后淡"。
- 约束：远层必须挂在一个能被 `[data-scrolled='true']` 与 reduced-motion 同时命中的伪元素上，走**同一条** 320/520ms 曲线。

### L6 丢失的能力（持平或更差，需明确）
- 按玻璃透明度计算远光透射：两者都没有，**持平**。
- "卡片盖住导航投影上缘"这种反向遮挡：B 靠 z 序天然成立，属于**收益**。
- 无 JS、关闭、纸媒：B **更稳**（不依赖观察器与几何判定），是收益。

### L7 代价转移（收益为主）
- 删掉：整个 SVG 层、每帧测量、`ResizeObserver`/`MutationObserver` 订阅、视口级 blur 滤镜、`v-if` 闪烁、`--depth-direct-band` 开关。
- 新增：一张固定渐变带（一次栅格化）+ 每张卡片一个 inset（静态）。滚动时两者都只做合成平移，不再重绘。

### 4.1 视觉损失（只列"看得见"的，按可见性排序）

| # | 现象 | 何时看得见 | 量级估计 | 缓解 | 残留 |
| --- | --- | --- | --- | --- | --- |
| V1 | **近/远交界的一阶强度台阶**：参照模型是"同一条光穿过两种接收面"，只随模糊渐变；B 是背景层与卡片各画一份，在卡片顶边外侧相接处可能形成一条 1–3px 的略亮/略暗细带 | 深色 + 高对比背景（aurora/art）最明显；浅色次之；flat/theme 基本看不出 | ±2–4/255 | 近层顶部值取"近 + 远在该处的贡献"（补偿式） | ±1–2/255（贴到眼前才可见） |
| V2 | **横向均匀性丢失（方向已更正）**：参照近层是"导航剪影 ∩ 卡片范围"——静止态两者等宽、滚动态导航**更宽**（`width: calc(100vw - 36px)`），两种情况下卡片都被完全覆盖，**在卡片上就是一条横向均匀的带**，与 B 的 `inset` 一致；真正露馅的是**反向**情形（卡片宽于导航、或卡片居中/窄卡片），此时参照会在卡片两端留下未被照亮的小段，而 B 沿边均匀照到两端 | 滚动态**不是**问题；窄/居中卡片会出现 | 同宽/更宽前提 <1–2/255；反向情形可达 ±α | 约束：只对与 shell 同宽（或更窄）的顶级读面生效 | 结构性前提 |
| V3 | **光带尾部是手写曲线**：B 的远层用 5–6 个色标近似高斯尾部，尾段形状与连续高斯不同 | 极暗背景上看"光带长度"；色标太稀时末段出现台阶 | 感觉短 3–8px；台阶可达 1–2/255 | 色标加密到 8–10 个，末段压到 α<1/255 | 需视觉校一次长度 |
| V4 | **"同一光源"一致性丢失**：参照远近同源（同 α 同色，只差 σ/位移/opacity）；B 两处独立定值，换档位时两处比例可能不同步 | 深浅两色并排比对、或切换"轻柔↔鲜明"时 | 比例偏差 ±3–5/255 | 两处的档位比例按同一系数生成（轻柔 = 鲜明 × 0.72 之类），并写进文档 | 单独看几乎不可见 |
| V5 | **贴边叠加**：卡片顶边紧贴导航下沿时，B 中卡片 inset 与导航远层在同一处相加；参照因遮罩互斥不会叠加 | 只在"正好贴边"的滚动位置，一段窄带 | +3–6/255 | inset 顶部留 1px 缓冲（`inset 1px 8px 20px`）或按 `.58` 同步淡出 | 无法感知"贴边"，属可接受近似 |
| V6 | **浅色机制观感差异**：浅色下参照是"上方有东西挡了光"（外部遮挡影）；B 的 inset 是把深灰画在卡片**内侧顶部**，观感更像"卡片自己顶部带灰"，且可能压住材质自带的 1px 顶高光 | 浅色 + 鲜明档 | 可见但难量化（观感而非亮度） | inset 从顶边下 1px 起、alpha 收一档 | 浅色下"光的来向"暗示变弱 |
| V7 | **滚动稳定性反而是收益**：参照版有拖影/闪回/台阶抖动；B 没有 | 滚动时 | — | — | 收益，与损失并列记录 |

### 4.2 锚点改变带来的债（B 最本质的代价）

参照模型的**两层都锚定在视口**（导航投影 = 一条"跟着导航走"的光）；B 把**近层锚点改成了卡片**（inset 是卡片自己的边）。这个换轴带来三条不可避免的视觉债：

| # | 现象 | 何时看得见 | 量级估计 | 缓解 | 残留 |
| --- | --- | --- | --- | --- | --- |
| V8 | **卡片顶光"永远在"**：参照只在卡片靠近导航（σ10、+8px，约 40px 内）时才照亮它；B 的 inset 无论卡片离导航多远都画 | 卡片从下方进入视口、离导航还有上百像素时（例如首页第二张卡上升中） | 整条顶光都是"多出来的"，≈ α | 无纯 CSS 解（要感知距离就得回到逐帧测量）；可只给"最上面那张卡"取消？同样要 JS | 结构性，需要用户裁决 |
| V9 | **光"粘在卡片上"**：参照的光随导航固定、卡片从光下穿过；B 的顶光随卡片滚动 | 滚动时看卡片顶边 | 观感差异（非亮度） | 无 | 结构性 |
| V10 | **滚动态远层的两条小差**：① 参照的远光带长度会随导航变宽一起拉伸（440ms），B 的渐变带是常量、不拉伸；② 参照把远层从卡片范围**完全裁掉**，B 的远层画在背景层上，会**透过半透明卡片**隐约透出（卡片玻璃约 30–50% 透光） | ① 展开动画期间；② 卡片顶边落在远层可达范围（约 96px）内 | ① 观感（光带不跟着变长）；② 约 2–4/255 | ① 接受或让远层随 `[data-scrolled]` 也做一次宽度变化（要动画 background-size，成本低但要另写）；② 把远层色标起点下移，避开卡片顶带 | ② 可压到 ≤2/255 |

**一句话总结这个债**：B 用"锚点的统一"换取了"近/远分档"——参照是**一个锚点、两种衰减**，B 是**两个锚点、各自定值**。所以 B 不可能"无限逼近"参照；它能做到的是"在卡片贴住导航的常见状态下几乎一致，在卡片远离导航时多出一条不该有的顶光"。

**A/B 的真正取舍**（决定前请只看这一句）：

```text
A（导航单层 box-shadow）＝ 锚点与参照一致（视口），但近/远只能同一个强度
B（背景渐变 + 卡片 inset）＝ 近/远分档保住，但锚点从视口变成卡片，代价是 V8/V9
```

若"卡片上升过程中不该有顶光"对你重要，应选 A；若"卡片上的光必须比背景上的光强"更重要，选 B 并接受 V8。

**优先级**：V1/V5 需肉眼裁决；V2 是结构性前提（滚动态反而最像参照）；V3 是参数精度；V4/V6 只有并排比对才看得出；**V8/V9 是 B 无法消除的结构性债，只能接受或改选 A**。

## 8. 结论与暂缓（2026-10-06，归档）

**决策：暂不实施 A 也不实施 B，保持现状**——接光层（`DepthReceivers.vue`）继续承担导航投影，卡片影继续用 `depth.css` 里的静态 `box-shadow`。

暂缓原因：两种替换均会改变既有空间关系，尚无足够性能与视觉证据支持实施。更详尽的原始讨论保存在本地、不纳入 Git 的 `docs/depth-projection-open-issue.md`；仓库中的当前实现与验证边界见 [接光层记录](depth-receivers.md)。本文保留历史设计与损失分析，不作为执行授权。






## 5. 验收标准（"无限逼近"要量化）

固定三个滚动位置（顶部 / 卡片贴导航 / 卡片滑出）各截一张，与 SVG 版逐像素比对：

```text
node tmp/png-diff.mjs  svg版.png  css版.png      # 平均/最大通道差
node tmp/analyze-glow-bands.mjs <png> center     # 只读正中一列（用户要求），查 1/255 平台带
```

判据：
- **卡片与背景交界带**（唯一必然有差异处）：平均差 **≤3/255**、最大差 ≤6/255；
- **其余区域**：平均差 **≤1/255**；
- 无新增等亮平台带（8bit 台阶）；
- 关闭 / 纸媒 / 浅色 / 深色 / 手机 五种状态各过一遍。

达不到就回到路线 A 或保留 SVG，不宣称"已逼近"。

## 7. 明确不宣称

- 本文是设计文档，**B 尚未实现**；所有误差数字是基于换算与经验的上限估计，必须由第 5 节的像素比对证实或推翻。
- 未做浏览器自动化（用户额度要求）；未做 GPU/帧率量化，不宣称"解决了卡顿"，只说结构上移除了逐帧测量与视口级模糊。
- 不改变导航本体配方（B 档、`--depth-glass-*`、320/520ms）与材质系统（main.css）。
