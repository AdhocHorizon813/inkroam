# 审美原则：让效果为阅读让路

这个站点有很多动效、材质和层次，但它们放在一起并不吵。原因不是每一样都很安静，而是它们朝同一个方向：**不抢阅读的注意力**。

这篇文档刻意不列实现——颜色、字体、缓动曲线的具体数值在 [visual-system.md](visual-system.md) 和 [motion-and-interaction.md](motion-and-interaction.md) 里。这里只回答一个问题：**当你想加一个效果时，怎么判断它该不该存在**。

## 一条主线：克制

站点的审美目标不是「第一眼惊艳」，而是「读十分钟之后仍然愿意读下去」。这两件事经常冲突：更大的标题、更强的对比、更明显的动效，都能在头两秒抓住人，也会让连续阅读变得更累。

所以每个效果都服从同一条判断：**它让阅读更好，还是让效果本身更好？** 如果一次改动的主要收益是「看起来更酷」，那它多半不该做。

## 动效：回应，而不是表演

### 位移很小

路由切换时，内容只从下方 10px 浮起；首页文章行悬停时，正文平移 7px、箭头朝右上 3px。动的是**重心**，不是距离。真正让人觉得「顺」的是节奏和曲线，而不是移动了多远。

### 入场慢而顺，离场快而脆

项目不用 `ease` 这类关键字，而是四条有性格的显式曲线：

| 曲线 | 性格 | 用在哪 |
| --- | --- | --- |
| `--ease-fluid` | 起步快、收尾极慢 | 路由入场、位移与颜色 |
| `--ease-settle` | 落位时几乎「贴」住 | 导航指示器、面板、缩放 |
| `--ease-panel` | 比 settle 略紧，专供面板 | 外观面板展开 |
| `--ease-exit` | 加速离场 | 关闭、淡出 |

多数入场在 420–520ms（路由入场稍长，620ms），离场压到 130–180ms。**关闭永远比打开快**——用户已经决定离开了，不该再让他等。

### 会停

`prefers-reduced-motion: reduce` 下，全局把时长压到 `.01ms`，而不是删掉动画。这样 `transitionend` / `animationend` 仍会触发，依赖这些事件的逻辑不会被悄悄打断。减少动效是「快进」，不是「取消」。

### 状态切换不做逐帧动画

切换视觉身份、材质这类大面积变化时，用 View Transitions 的快照过渡，而不是让几百个元素的颜色逐帧变化。后者在低端设备上会掉帧，而**卡顿本身就是最差的美学**。

## 层次：让表面有触感，但别浮起来

### 三种材质是同一间屋子里不同的光

液态玻璃、亚克力、云母三档材质的差异被刻意压小。它们不是三种风格，而是同一种表面在三种光照下的样子——切换时应该感觉「换了光」，而不是「换了个网站」。

### 玻璃的分寸

玻璃拟态最容易做坏的两处是「太亮」和「太浮」。这里的做法是：边框只有 8–10% 的白；顶部留一条 1px 内高光，暗示受光方向；外阴影轻到几乎察觉不到。结果是有厚度、但不飘。

早期版本用过 115° 白色渐变加遮罩的「边缘高光」方案，后来主动关掉了——**它很好看，但和克制的方向相反**。

### 背景与遮罩是联动的

遮罩越强，底图越淡，两层由同一个变量反向驱动。这样无论用户把遮罩拉到哪个位置，正文对比度都在安全范围内。审美决定不能建立在「用户不会拉到极端」的假设上。

## 颜色：一条强调色，其余交给灰阶

整个界面只有一条强调色，其余层级全部靠灰阶和透明度区分。强调色的职责是**指路**——链接、当前项、章节符号——而不是装饰。

两个和审美直接相关的约定：

- **派生色预计算**：强调色的深浅变体在根节点算一次。若改成每个元素现算，切换主题时要重复计算成百上千次，掉帧会让「从容」瞬间消失；
- **文本用加强色**：正文里的强调色会混入前景色，保证在深色背景上依然够亮。好看的前提是看得清。

## 排版：留白是内容的一部分

- 正文列宽上限 720px，是中文长文比较舒服的阅读宽度；
- 行高接近 2，给中文足够的呼吸；
- **大标题收紧字距，小号全大写标签拉开字距**——方向相反，目的一致：让字号和字距表达同一种气质；
- 大标题用 `text-wrap: balance`，避免最后一行只剩一两个字；
- 章节用 `§` 作为标记：一个符号就够，不再加图标或色块。

## 交互：先测量，再出现

几处细节都遵循同一个模式——**不要让用户看见「计算」的过程**：

- 导航指示器初始透明，测量完成后才淡入，避免首帧从左上角飞过来；
- 头部滚动展开只改宽度和外边距，不改高度和内边距，所以内容不会跳动；
- 外观面板从触发器的位置「长」出来，而不是在屏幕角落凭空出现；
- 悬停位移只在精确指针设备上启用，触屏点按不会残留位移状态。

## 把审美交给读者

外观面板允许调整视觉身份、明暗、强调色（12 个预设）、三种材质、四种背景，以及各自的模糊强度。这些选择写进 `<html>` 的 `data-*` 属性和内联 CSS 变量，CSS 只认属性、不认组件状态。

这带来两个结果：

1. 两套视觉可以长期共存、互不污染；
2. **默认值只是「被校准过的一档」，不是唯一正确的答案**。站点给出的是范围和判断标准，具体偏好归读者。

## 被刻意舍弃的东西

下面这些都能做出「好看」，但和这条主线冲突，因此不采用：

- 弹跳 / 回弹曲线——活泼，但会打断阅读节奏；
- 超过 600ms 的入场动画——用户已经看完内容了，动画还没结束；
- 多色渐变与彩色阴影——颜色一多，强调色就不再是「指路」；
- 厚重的投影和描边——廉价感的主要来源；
- 全屏粒子、光标跟随之类的装饰性效果——它们服务于「看」，不是「读」。

## 判断一个改动是否合格

按顺序问自己：

1. 它服务于阅读，还是服务于效果本身？
2. 把它关掉，页面变差了吗？如果没变差，它可能本来就不必要。
3. 减少动效时它还成立吗？
4. 它复用了现有的缓动 / 颜色 / 材质变量，还是又写死了一套？
5. 触屏上会不会残留悬停状态？

五个问题里有一个答不上来，就先别合。
