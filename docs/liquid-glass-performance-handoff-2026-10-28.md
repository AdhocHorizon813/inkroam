## 最高优先级的三组嫌疑

这些都是待验证的原因，不是已经测定的瓶颈。

### A. HiDPI 位移图被我一起放大了

文件：`app/utils/glass-quality.ts`。

起点 AA 关闭时 mapScale 大致为 1，大面板还会受最长边 1024 限制；本轮改为按 DPR，最大 2，面积目标约 150 万像素，但最低为 1。

这消除了低于 CSS 像素的位移图，却让 DPR=2 的常见面板即使 AA 关闭也可能增加四倍贴图像素。**位移图分辨率不等于背景内容的渲染分辨率**。此前为了修“内容像素感”一起提高 mapScale，可能是成本增加而收益不足的地方，应该首先隔离。

AA 当前只改变 `edgeSoftness`（0 / 0.8 CSS px），开关本身已经不再把 mapScale 翻倍。不要沿用旧断点的“AA=2倍采样”说明。

临时对照检查：仅在本地诊断分支/可撤销补丁里，把大面板 mapScale 固定为 1，保持 blur、折射、染色、动画和设备 DPR 不变。记录实际生成贴图尺寸、次数、耗时，再比较肉眼像素感。不能仅凭这项检查便永久降低所有控件质量。

### B. 真实采样后，大量独立滑块滤镜叠在一个展开面板中

文件：`app/utils/glass-controls.ts`、`app/components/ExperimentalGlass.client.vue`。

原指示器位于有 mask 的滚动区内，背景采样会被截断，可能只见到平坦/透明的局部背景。本轮把光学层 portal 到面板内、滚动遮罩之前，原文字和交互留在原处。

这修正了采样位置，但阅读面板中约十几到二十组指示器/滑条各自拥有一套 SVG backdrop-filter。父面板本身也有滤镜，并同时进行 transform 和 clip-path 展开。恢复真实采样后，嵌套背景依赖与多组滤镜可能显著增加 GPU 合成/栅格成本。

临时对照检查依次比较：面板玻璃保留但控件用原样式；只保留一组控件玻璃；恢复全部控件玻璃。必须明确这是定位用的临时隔离，不能交付一个禁用滑块玻璃的“修复”。如果瓶颈在此，下一步研究共享背景采样/合并光学层/只维护可见控件，而不是继续加 will-change。

检查 portal 还有没有不必要的几何读取和写入。当前每个控件在 render 中读取 host/panel/scroller 的 rect，并写光学层位置；scroll 时各自排队 RAF。测是否发生交错的 style write → layout read。统一批量读取再批量写入可能有帮助，但没有证据前不要大重构。

### C. 新正文卡片背景增加了全局合成成本

文件：新增 `app/utils/glass-content.ts`，以及 `experimental-glass.ts` 的候选收集。

已按用户授权接入 `.hero, .latest-section, .manifesto, .standard-page, .article-page`。光学层是原卡片内的绝对定位装饰层，不过滤文字；长文只使用视口高 + 192px 的 tile，`bleedTop/bleedBottom` 把非真实卡片边界的横向反光移出可视区。滚动中大部分时候仅移动 tile，不应生成新形状贴图。

**这一实现尚未完成实际浏览器或完整生命周期验证。** 即便贴图尺寸受控，正文和上层菜单叠加也可能增加背景依赖。先临时排除正文候选，再比较面板展开，不能把此差异混同于 A/B。若问题只在正文开启时出现，再查背景采样依赖、层级和无变化更新。

## 已做但尚无 FPS 证据的优化

`app/vendor/liquidglass/liquid-glass.js`：

1. Blink 保持稳定 filter ID；只让 WebKit 继续更换 ID 和做 60/250ms 延时刷新。
2. 形状按设备像素量化后生成缓存 key，避免弹簧尾部无意义的小数尺寸产生近似 PNG。
3. backdrop 路径把磨砂移到原生 `blur(...) url(#filter)`，SVG 内不再做 GaussianBlur；content 模式保持上游路径。
4. fit 的 backdrop 图不再做两道恢复 outside 的合成。需关注圆角部分透明像素是否出现视觉差异；源码检查不等于像素等价。
5. ResizeObserver 忽略尺寸未变的回调。

`AppearancePanel.vue` / `MusicPlayer.vue`：常驻面板及其控件改为始终注册（仅漫光玻璃开启时才创建引擎），收起时预备，关闭不立即销毁。避免每次展开时才 import/生成/解码后换材质。**代价是常驻实例增多**；需要判断是否预备了不可见但仍在重绘的控件。不要误把注册常驻说成音频加载：本轮没有改变音乐懒加载。

## 其它本轮改动，排查时不要误删

- 底部两个入口统一为宿主直接 backdrop，移除旧负 z-index 注入层，未复制其文字。
- 玻璃 CSS 屏蔽旧 `.appearance-panel::after` 渐变。
- `rimGlow=0` 只保留几何边缘窄反光；`specularAmbient` 保持浅色 0.08、深色 0.85。它是背景染色近似，不是光线追踪。
- `boundedBezel=true` 让 bevel 不超过圆角半径，避免大面板小圆角在内部法线换向处仍有非零位移，形成折射断缝。
- 图片灯箱的关闭/前后按钮、PDF 工具栏/查找栏已挂接。灯箱始终使用深色配方，避免跟随全局浅色出现低对比文字。图片/PDF 画布本身不加滤镜。
- 新增 `bleedTop/Bottom` 支持正文 tile；内核声明、类型和接入方需要一起维护。

## 建议排查顺序与记录方式

1. 保存工作区 diff 和新文件副本；阅读本文件及最新断点。不要擅自 stash/reset 丢掉上下文。
2. 检查本地服务是否实际运行，不默认 localhost:3000 可用。不修改设备 DPR 或浏览器缩放来“改善”数据。
3. 先为内核添加可关闭的诊断计数：renderLensMap 次数/总像素/耗时、create/destroy/活动实例、flush 次数、filter ID 变更次数。使用 performance.now 汇总，**不要逐帧 console.log**。区分创建/解码与浏览器绘制。
4. 在保持设备/主题/壁纸/通透度/AA/层次感/视口/滚动位置一致的前提下，按 A → B → C 单变量隔离。包括首次打开和第二次打开，至少分别记录；不要只对比冷启动与暖缓存。
5. 如果开合期间 renderLensMap 数量为 0 仍卡，重点转向 GPU raster/compositor/嵌套 backdrop，别继续只优化 PNG 生成。
6. 如果很多控件反复改尺寸/图，查真实尺寸变化、弹簧 pressure、Vue 更新与 ResizeObserver 的重复写入。不要把“设置了稳定 ID”当作没有重绘的证据。
7. 一次只保留有证据的优化，恢复临时诊断隔离。保留现有动效和质感，在断点写明未证明的项目。

用户愿意提供 trace 时：同一可见前台浏览器，固定同一页面，分别录漫光玻璃关闭/开启、AA关闭/开启的短录制；每份包含首次及再次开合，记录浏览器版本、实际GPU、DPR与缩放。不要后台/遮挡运行后拿结果解释性能，不用 Nuxt 构建 trace 代替页面 trace。
