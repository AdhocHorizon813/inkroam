# Inkroam Modern 深色模式导航条材质优化规范

## ------在现有"层级感系统"基础上，减少自发光廉价感与塑料感

> 适用范围：`modern` 视觉下的 **深色模式导航条**
>
> 当前本地版本已经新增了公开仓库中不存在的"层级感系统"，但目前仅导航条完成接入。
>
> 因此本次优化：
>
> -   **不重做层级系统**
> -   **不扩大到全站**
> -   **不假设公开仓库包含最新实现**
> -   **不要求修改 Article / Dropdown / Content Surface**
> -   只针对当前已经接入层级感系统的导航条进行材质与光照校准
>
> 公开仓库仅用于参考现有 `modern / classic`、背景系统、Accent
> 系统、Liquid / Acrylic / Mica 材质系统以及 AppearancePanel 配置架构。
>
> 具体层级实现、选择器和变量，以本地最新代码为准。

> **2026-10-05 补充（读本文前先看这条）**：本文"压低 Glow"只针对**外围、无来源、无轮廓的大面积亮晕**。导航条上另有两处发光是用户明确要求**保留并增强**的——玻璃面的整面受光、以及向下投射的光条——不要在"统一压低 Glow"时一并砍掉。本地代码基线见第 40 节，术语分层见第 43 节，已经写成校验不变量的硬约束见第 42 节。

------------------------------------------------------------------------

# 1. 当前目标

当前导航条已经不再只是普通的：

``` text
background
+
border
+
blur
```

而是接入了一套新的"层级感系统"。

这意味着它现在需要同时表达两件事：

``` text
1. 它是什么材质
2. 它处于页面中的什么深度
```

目前截图中最大的问题不是层级感不足，反而是：

> **层级感已经出现，但部分视觉信号被较强的外部亮晕解释成了"自发光"。**

因此本次优化目标不是压平导航条，而是：

> **保留甚至强化真实层级，同时减少"灯带 / 塑料盒 / RGB
> 面板"的视觉解释。**

------------------------------------------------------------------------

# 2. 当前问题的视觉来源

当前导航条已经有明显的悬浮感，这一点本身是成立的。

问题主要来自：

``` text
导航条外围的大范围亮区
+
边缘高亮
+
半透明材质
+
较大的圆角
+
Accent 染色
```

这些元素叠加后，人眼容易把它理解成：

> 一个正在主动发光的半透明塑料盒。

而不是：

> 一个处于前景层、受到环境光照亮的悬浮玻璃面板。

------------------------------------------------------------------------

# 3. 最重要的区别：Layer ≠ Glow

新的层级感系统必须避免一个误区：

> "层级越高，Glow 越强。"

层级主要应该由：

``` text
遮挡关系
Shadow
背景模糊
Surface 明度
边缘分离
局部对比
```

表达，而不是 Glow 强度。

也就是说：

``` text
Depth ↑
```

不应该自动等于：

``` text
Emission ↑
```

------------------------------------------------------------------------

# 4. 深色模式中的正确空间逻辑

当前导航条应该被理解为：

``` text
        页面背景
            ↓
     环境光 / 背景色
            ↓

   ┌────────────────┐
   │     Navbar     │
   │    Floating    │
   └────────────────┘
            ↓
       Neutral Shadow
            ↓
         页面主体
```

而不是：

``` text
        ✦ ✦ ✦ ✦
    ✦ ┌──────────┐ ✦
    ✦ │ Navbar   │ ✦
    ✦ └──────────┘ ✦
        ✦ ✦ ✦ ✦
```

前者是悬浮，后者是发光。

------------------------------------------------------------------------

# 5. 当前深色模式下应该保留什么

不要因为出现塑料感，就把现在已有的效果全部删掉。

应该保留：

-   当前悬浮层级
-   圆角
-   半透明
-   Blur
-   环境色响应
-   顶部 / 边缘高光
-   与背景的分离
-   Accent 轻微影响
-   深色玻璃感

问题不是这些元素存在，而是：

> **它们目前有部分信号过于集中在"外发光"上。**

------------------------------------------------------------------------

# 6. 本轮不应该做什么

不要：

``` text
直接删掉所有 shadow
直接删掉所有 glow
改成完全不透明 navbar
把 navbar 改成黑灰扁平矩形
取消环境色
取消玻璃感
取消层级系统
```

这些都会把问题从"太像发光塑料"变成"太像普通 SaaS Header"。

------------------------------------------------------------------------

# 7. 优先保留 Shadow，压低 Glow

如果当前导航条同时存在：

``` text
黑色空间阴影
+
Accent / 蓝色 Glow
```

应该优先：

``` text
保留空间阴影
降低 Accent Glow
```

因为二者表达不同东西。

## Shadow 表达

``` text
Navbar 离背景有距离
```

## Glow 表达

``` text
Navbar 自己正在发光
```

当前真正需要的是前者。

------------------------------------------------------------------------

# 8. Glow 不必完全删除

可以保留非常弱的外部氛围。

但它应该满足：

``` text
看不到清晰轮廓
看不到明显光圈
不会四周均匀发亮
不会比 Shadow 更显眼
```

理想状态：

> 关闭以后会感觉少了一点空气感。

而不是：

> 打开以后明显看到一圈蓝色。

------------------------------------------------------------------------

# 9. 不要让 Glow 紧贴轮廓

最廉价的一种效果是：

``` text
圆角矩形
+
紧贴圆角矩形的一圈同色亮晕
```

因为这太容易被识别为：

``` css
box-shadow: 0 0 ...;
```

如果必须保留外部环境亮度：

-   范围可以大
-   强度必须低
-   边界必须不可识别
-   不要严格复制 Navbar 轮廓
-   不要四边完全对称

------------------------------------------------------------------------

# 10. Shadow 应该更加承担"层级"

深色模式下，Navbar 的空间分离更适合使用中性深色阴影。

例如概念上：

``` css
box-shadow:
  0 12px 36px rgba(0, 0, 0, .20);
```

具体数值以本地层级系统为准。

重点不是这个数值，而是：

> **Depth 应主要由暗部建立。**

这会比增加亮部更加自然。

------------------------------------------------------------------------

# 11. 顶部高光比整圈亮边更重要

深色玻璃如果四条边一样亮，很容易塑料化。

更自然的是：

``` text
顶部：稍亮
左右：较弱
底部：很弱
```

因为它暗示光来自环境中的某个方向，而不是整个对象自己发光。

------------------------------------------------------------------------

# 12. 避免四边均匀白边

当前如果导航条使用类似：

``` css
border: 1px solid rgba(255,255,255,.1);
```

整个轮廓会非常完整。

在深色背景上，这容易形成透明塑料盒描边。

更好的方向是：

``` text
基础 Border 很弱
+
顶部额外 Highlight
```

例如：

``` css
border: 1px solid rgba(255,255,255,.04);

box-shadow:
  inset 0 1px 0 rgba(255,255,255,.07),
  ...;
```

这样顶部仍然能被"读出来"，但不会整圈发白。

------------------------------------------------------------------------

# 13. Accent 的职责

由于 Accent 可以修改，所以不能把当前蓝灰色视为固定设计。

但 Accent 仍然可以轻微进入 Navbar。

正确方式是：

> **Tint，而不是 Emission。**

即：

``` text
Navbar 稍微受到 Accent 染色
```

可以。

但：

``` text
Navbar 向外发 Accent 光
```

应该非常谨慎。

------------------------------------------------------------------------

# 14. Accent 不应该控制层级强度

尤其不要建立：

``` text
Accent 越鲜艳
↓
Glow 越明显
↓
Navbar 越“浮”
```

否则用户切换到高饱和粉色 / 绿色 / 橙色时，层级系统会退化成霓虹灯系统。

------------------------------------------------------------------------

# 15. 背景仍然是变量

即使本轮只处理深色模式，也不能假设背景固定是当前截图里的深蓝图像。

当前背景仍可能是：

``` text
flat
theme
aurora
art
dusk
custom
```

所以导航条的层级表达必须在不同背景下成立。

------------------------------------------------------------------------

# 16. 当前截图只是一个调试样本

当前截图可以帮助判断：

``` text
Glow 太强
Shadow 与 Glow 比例不协调
顶部亮区过明显
```

但不能据此写死：

``` text
蓝色
背景亮度
图片色调
```

------------------------------------------------------------------------

# 17. 深色 Flat 是重要测试

如果 Navbar 在：

``` text
dark + flat
```

下仍然有清楚层级，说明层级系统本身成立。

如果只有放在 `art / dusk`
图片背景上才显得悬浮，说明当前层级仍然过度依赖背景内容。

------------------------------------------------------------------------

# 18. Theme 背景是 Accent 压力测试

如果背景本身就是：

``` text
--modern-accent
```

那么 Navbar 再使用大量：

``` text
Accent Border
Accent Glow
Accent Tint
```

会全部糊在一起。

因此：

> **Theme 背景下尤其要依赖中性明暗关系，而不是主题色对比。**

------------------------------------------------------------------------

# 19. Aurora 是 Glow 压力测试

Aurora 本身已经提供：

``` text
柔光
颜色渐变
环境光晕
```

Navbar 不需要再承担大量 Glow。

否则会变成：

``` text
Background Glow
+
Navbar Glow
```

互相竞争。

------------------------------------------------------------------------

# 20. Custom 是鲁棒性测试

Custom 背景可能极亮、极暗、高饱和或复杂。

因此 Navbar 必须主要依靠：

``` text
Surface
Blur
Border
Shadow
Layer
```

建立自己，而不是依赖"背景刚好是深蓝色"。

------------------------------------------------------------------------

# 21. Plastic Feel 的几个典型来源

深色玻璃最容易塑料化的组合：

``` text
高透明
+
高 Blur
+
完整白边
+
大圆角
+
蓝色 / Accent Glow
+
均匀渐变
```

这些效果单独都不一定有问题。

问题在于：

> **同时全部存在，并且强度都比较高。**

因此优化方向不是删掉其中一个，而是重新分配权重。

------------------------------------------------------------------------

# 22. 建议的视觉权重

Navbar 的质感来源可以按大致优先级理解：

``` text
1. Layer / Depth
2. Surface 明暗
3. Backdrop Blur
4. Neutral Shadow
5. Edge Highlight
6. Accent Tint
7. Glow
```

Glow 应该排在最后。

------------------------------------------------------------------------

# 23. Navbar 本身不要过亮

在深色模式下，如果 Navbar
整体亮度明显高于周围太多，它会像一块发亮的半透明塑料。

更好的方式是：

``` text
整体仍然偏暗
+
通过局部高光和透明度显示材质
```

而不是整个 Surface 亮起来。

------------------------------------------------------------------------

# 24. Layer System 应该通过"局部对比"工作

层级感不是：

``` text
整块 Navbar 比背景亮很多
```

而是：

``` text
上缘有高光
下方有暗影
中间与背景存在透射差
边缘有轻微分离
```

这种局部变化会比整体提亮更加自然。

------------------------------------------------------------------------

# 25. 内高光应该保留

对于当前已经建立层级感的 Navbar：

``` css
inset 0 1px 0 ...;
```

这一类效果通常值得保留。

它能表达：

``` text
材质边缘正在接收光
```

比外发光更加合理。

------------------------------------------------------------------------

# 26. 可以加入非常弱的纵向材质变化

如果当前 Surface 完全是统一颜色：

``` text
Top = Center = Bottom
```

会更像塑料板。

可以考虑非常弱的纵向变化：

``` text
顶部稍亮
↓
中间正常
↓
底部略暗
```

但这个变化必须弱到：

> 看不出明显渐变。

------------------------------------------------------------------------

# 27. 不要做"玻璃高光条"

避免：

``` text
顶部明显白色渐变
大片镜面反射
清晰亮斑
```

那会从"塑料"变成"2000 年代 Aqua UI"。

当前应该保持更现代、更克制。

------------------------------------------------------------------------

# 28. 当前 Layer System 应先稳定 Navbar

由于现在只有导航条接入了新层级系统：

> **暂时不要为了"全站统一"去给其他组件强行套同样层级。**

当前更合理的开发顺序是：

``` text
先把 Navbar 做对
↓
确定 Layer 规则
↓
观察一段时间
↓
再决定哪些 Surface 需要复用
```

------------------------------------------------------------------------

# 29. 不要提前规定 Article 等组件层级

由于当前本地层级系统尚未扩展到其他组件，本文不应该提前规定：

``` text
Article 一定 Level 1
Dropdown 一定 Level 3
```

这些等后续实际接入时再根据视觉关系决定。

否则会让当前实验性层级系统过早僵化。

------------------------------------------------------------------------

# 30. 当前阶段需要验证的只是

``` text
Navbar 是否真正“浮”
```

而不是：

``` text
Navbar 是否真正“亮”
```

这两个概念要严格区分。

------------------------------------------------------------------------

# 31. 推荐测试 Accent

虽然当前是深色模式，但 Accent 仍应测试至少：

``` text
蓝灰
紫色
粉色
橙色
绿色
低饱和灰色
```

重点观察：

> 换 Accent 后 Navbar 会不会瞬间变成对应颜色的霓虹灯。

如果会，说明 Accent 与 Emission 仍然绑定过强。

------------------------------------------------------------------------

# 32. 推荐测试 Background

至少测试：

``` text
flat
theme
aurora
art
custom
```

不需要一次优化全站，只观察 Navbar。

------------------------------------------------------------------------

# 33. Blur 测试

因为 Blur 可调，Navbar 应测试：

``` text
低 Blur
当前默认
高 Blur
```

不能出现：

``` text
Blur 一降低
↓
Navbar 层级彻底消失
```

否则说明：

> **Layer System 实际上只是 Blur System。**

------------------------------------------------------------------------

# 34. Glow-Off Test

开发时临时关闭所有 Navbar Accent Glow。

然后观察。

如果 Navbar 仍然：

``` text
悬浮
有材质
与背景分离
有空间关系
```

说明层级系统成功。

如果立刻塌掉：

> 当前层级仍然依赖 Glow。

------------------------------------------------------------------------

# 35. Grayscale Test

把截图转灰度。

如果 Navbar 仍然明显浮在页面上：

> 层级结构成立。

如果变灰后 Navbar 完全融入背景：

> 当前主要依赖主题色，而不是结构。

------------------------------------------------------------------------

# 36. Squint Test

眯眼观察或把截图缩小。

应该看到：

``` text
一个前景 Navbar
+
一个后方页面
```

而不是：

``` text
一条蓝色光带
```

------------------------------------------------------------------------

# 37. 本轮验收标准

完成后应满足：

-   [ ] Navbar 仍然保持当前明显的悬浮层级
-   [ ] 降低 Glow 后层级不会消失
-   [ ] 深色模式整体氛围不被破坏
-   [ ] Navbar 不再像主动发光的塑料盒
-   [ ] 外围亮区不再形成清楚的矩形光圈
-   [ ] Shadow 比 Glow 更负责空间分离
-   [ ] 顶部 Highlight 比四边完整亮框更明显
-   [ ] Accent 更换后不会自动变成霓虹灯
-   [ ] `flat` 背景下层级仍成立
-   [ ] `theme` 背景下不会与 Accent 糊在一起
-   [ ] `aurora` 下不会 Glow 叠 Glow
-   [ ] `custom` 下不依赖特定背景颜色
-   [ ] Blur 调整不会破坏整个 Layer System
-   [ ] 不影响 classic
-   [ ] 不破坏现有背景和主题色配置
-   [ ] 不修改尚未接入新层级系统的组件
-   [ ] 不把 Navbar 改成普通黑灰 SaaS Header

------------------------------------------------------------------------

# 38. 当前阶段的一句话原则

> **Navbar 要让人感觉它离背景更近或更远，而不是让人感觉它亮了多少。**

层级感来自：

``` text
空间关系
```

不是：

``` text
发光强度
```

------------------------------------------------------------------------

# 39. 最终目标

当前导航条已经有了新的层级方向。

本轮不是重新设计它，而是把这套方向从：

``` text
悬浮 + 发光
```

进一步校准成：

``` text
悬浮 + 材质 + 环境响应
```

最终希望用户看到它时首先产生的是：

> **"这是一块悬浮在页面上方的深色玻璃界面。"**

而不是：

> **"这是一条带主题色灯带的半透明塑料导航栏。"**

------------------------------------------------------------------------

# 40. 本地实现基线（2026-10-05，以代码为准）

前面反复出现的"以本地最新代码为准"在这里落成事实，读任何建议前先对齐这一节。

## 命中条件与开关

``` text
app/assets/css/depth.css
  ├─ 在 main.css 之后加载（nuxt.config.ts 的 css 数组第三项）
  ├─ 只匹配 :root[data-visual='modern'] 且 data-depth 为 soft / defined
  └─ 关闭（off）、纸媒、classic 一律不命中
开关：阅读外观 → 层次感 → 关闭 / 轻柔 / 鲜明
      默认关闭，存 v5 偏好，独立于「默认设置」，恢复默认＝关闭
```

## 导航玻璃（`.site-header::after`，透明装饰层）

``` text
content:''  position:absolute  inset:0  border-radius:inherit  pointer-events:none
box-shadow:
  inset 0 0 12px 200px var(--depth-glass-glow-inner)     ← 玻璃面整面受光（无上下偏移）
  inset 0 1px 0 var(--depth-glass-top)                   ← 顶部 1px 内高光（本文 11/12/25 节的落地）
  0 var(--depth-glass-band-y) var(--depth-glass-band-blur)
    var(--depth-glass-band-spread) var(--depth-glass-light)   ← 向下光条；浅色时是遮挡影
（贴轮廓的 0 0 14px 外发光与 --depth-glass-glow token 已按本文第 9 节删除）
```

| token | 深色 轻柔 / 鲜明 | 浅色 轻柔 / 鲜明 |
| --- | --- | --- |
| `--depth-glass-light`（光条 / 遮挡影 alpha） | `rgb(220 230 248 / .20)` / `.30` | `rgb(24 30 40 / .11)` / `.15` |
| `--depth-glass-band-y / -blur / -spread` | 18px / 48px / -6px | 16px / 40px / -8px |
| `--depth-glass-top`（顶部 1px 内高光） | `rgb(255 255 255 / .06)` / `.08` | transparent |
| `--depth-glass-glow-inner` | `rgb(226 234 250 / .12)` / `.16` | transparent |
| `--depth-element-glow` | 12% / 16% | 0% |

浅色**没有**发光层：`--depth-glass-glow*` 与 `--depth-element-glow` 恒为 transparent / 0%，浅色里唯一的颜色来自彩标那层主题色投影。

## 元素级（跟随 sticky 导航；点与命中区不动）

``` text
导航字形（.brand > span:last-child 与 .main-nav > a:not(.nav-search)）
  text-shadow：近（--depth-project-y / -blur）+ 远（--depth-project-far-y / -far-blur）
               + 一层零偏移 0 0 8px 光晕（深色生效；浅色因 --depth-element-glow: 0% 全透明）
搜索图标（.nav-search svg）
  filter：同方向 drop-shadow + drop-shadow(0 0 6px) 零偏移光晕
```

# 41. 8bit 台阶：为什么"再调低一点"会让横带更明显

2026-10-05 用用户提供的裁切图逐像素实测（**只读正中一列 x=153，不做行平均、不做平滑**；脚本 `tmp/analyze-glow-bands.mjs`，center 模式）：

``` text
玻璃体 y=0–26    RGB(18,35,57)   亮度 33.0   平线
玻璃体 y=27–39   RGB(19,35,57)   亮度 33.2   平线（+0.2 台阶）
最亮线 y=42      RGB(70,83,99)   亮度 81.4
y=43 起          48.9 → 34.6 衰减，但方向反转 8 次
亮带依次         81.4 → 48.9 → 38.5(y=61) → 36.5(y=68) → 34.9(y=83)
相邻级只差       0.1 – 0.7 / 255
```

``` text
横带 = 多个极弱图层落进同一批 8bit 色阶格子后，平台被 1/255 的台阶切开
再调低既有的弱层，只会让台阶更干净、更明显
正确方向：减少层数 + 让梯度更陡
```

本轮据此删掉了 54px 宽衰减层（最弱、台阶最密的一条），并把光条几何拆成 `--depth-glass-band-*` 单独控制。**任何"把某层再调低"的建议都要先回答：台阶会不会更显眼。**

# 42. 与 `scripts/check-depth.mjs` 不变量的对齐

本文若出现"删掉光条 / 把玻璃发光归零 / 给 `::after` 加背景填充 / 覆盖材质阴影"，目前**改不进去**：校验脚本会直接失败。当前强制项：

``` text
所有规则必须 opt-in modern + soft/defined，且不得命中 .article-page / .hero / .latest-section / .standard-page
::after 只允许 content position inset padding border-radius pointer-events background mask mask-composite opacity transition box-shadow
其余规则只允许 background-image overflow text-shadow filter position 与 --depth-*
box-shadow 只允许出现在 .site-header::after 与 .site-header .brand-mark::after
filter 只能是搜索图标的 drop-shadow；text-shadow 只能是导航字形
玻璃 ::after 不得有 opacity / filter；background 只允许 ≤3% 的 linear-gradient（极弱材质渐变，禁实心填充，禁 Accent 驱动表面）
深色自发光只在 dark 作用域；浅色必须 transparent / 0%
内部受光必须是无上下偏移的整面光（inset 0 0 …），spread ≥ -8px，alpha ≤ .25，内层 ≤ 2 条
玻璃 ::after 不得出现贴轮廓光晕（任何非 inset 的 `0 0 Npx` 层），且必须恰好一条 `inset 0 1px 0` 顶部高光
向下光条的 blur 必须落在 16–64px（禁止极弱宽衰减尾巴回来）
深色光条 alpha ≥ 内部受光 alpha；浅色遮挡影 alpha < 深色光条
光条几何必须走 --depth-glass-band-*
深色元素投影强度必须 > 浅色；浅色彩色透光 ≥ 15%
Scrolled（[data-scrolled='true']）必须用 40–90% 的 opacity 整体淡出（面越大单位面积光效越弱）：展开方向在 scrolled 规则上走 `opacity 320ms cubic-bezier(.22, .8, .3, 1)`，收起方向在基础规则上走 `opacity 520ms cubic-bezier(.4, 0, .2, 1)`，两个方向必须非对称
玻璃的过渡只能写 opacity：禁止 transition box-shadow/background（逐帧整屏重绘＝卡顿）；也禁止 `--ease-fluid` 那样的前沿陡峭曲线用在光效上（前 16% 走完约 95%＝突变感）
Scrolled 的最终 A/B：只有外部环境光（`--depth-glass-light`）允许在 scrolled 下再降约 15%（深色 .17/.26、浅色 .095/.13）；本体亮度、顶部高光、几何、blur 一律不动；用户已判定采用 B（Navbar 就此冻结）
```

要突破其中任一条，必须同时改脚本并在 `docs/depth-design.md` 说明理由，不能只改 CSS。

# 43. 术语对齐：本文说的 Glow 到底是哪一层

本文第 8、9 节反对的是**外围、无来源、无轮廓的大面积亮晕**。本地导航条一共有五处发光/投影，处置各不相同：

``` text
① 外围宽衰减层（曾经的 54px 一带）   → 已删除，是本文要压的对象
② 贴轮廓弱外发光 0 0 14px            → **已按本文第 9 节整层删除**，token 也删掉，不要加回来
③ 玻璃面整面受光（inset）            → 用户要求保留并增强（“它本身自发光不够”）；浅色没有这一层
④ 向下投射的光条                     → 用户要求保留并增强（“配不上现在的自发光”）
⑤ 元素级投影与光晕                   → 保留字形/图标的零偏移光晕（用户要的元素自发光）；彩标的**主题色光晕已删除**，只留向下投的 Tint
```

即：**压"外围"，不压"面内"与"被元素照亮的去向"。** 用户 2026-10-05 明确授权"深色玻璃可以略微发光"，该授权取代更早的"深色玻璃绝不发光"。

# 44. 浅色模式（本文原本未覆盖）

浅色不是深色的镜像，机制不同，不能整段套用"压低 Glow"：

``` text
浅色 = 遮挡影（--depth-glass-light 用深灰 rgb(24 30 40)）+ 文字/图标遮挡影 + 彩标彩色透光
浅色不引入任何发光 token（glass-glow / glass-glow-inner / element-glow 恒为 transparent / 0%）
浅色光条必须弱于深色光条（两档要能区分），几何单独一套：16px / 40px / -8px
```

本轮浅色也做了校准（用户："浅色的强度也有点不够""看不清浅色的彩色玻璃效果"）：

``` text
遮挡影 alpha        .065 / .095  →  .11 / .15
光条几何            14 / 30 / -12  →  16 / 40 / -8
彩标彩色透光         8% / 12%  →  18% / 26%
浅色文字遮挡影强度   6% / 2%、10% / 3%   保持未动
```
