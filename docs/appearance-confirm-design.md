# 默认设置确认弹窗：视觉与动效规范

记录日期：2026-09-26。以 `app/components/AppearancePanel.vue` 的原生 dialog 和 `app/assets/css/main.css` 的 `.appearance-confirm` 为实现依据。这是当前实现的设计说明，不是 Apple 官方数值，也不代表所有浏览器已完成视觉验收。

## 设计定位

这是一次需要用户停下来决定的设置确认，不是文章卡片、通知或独立页面。目标是「柔和、有触感、清晰且有回应」。参考 Apple 的 [Materials](https://developer.apple.com/design/human-interface-guidelines/materials)、[Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts) 与 [macOS 27](https://www.apple.com/os/macos/) 的设计方向；具体尺寸、颜色与时长是为 Inkroam 选择的，不是对原生窗口的像素复刻，也没有实现系统级 Liquid Glass 光学渲染。

相比 Inkroam 原有偏纸媒、安静的阅读语言，这个弹窗更强调交互的存在感：居中聚焦、柔软轮廓、小幅缩放、明确的触按反馈。这种「活力」来自状态变化有节奏，而不是增加颜色、装饰或大幅弹跳。它适合短暂的决策层，不应直接推广到长文正文。

## 结构与阅读顺序

1. 设置图标：提示这是一项外观操作，不用警告符号制造危险感。
2. 标题：明确启用或禁用默认设置。
3. 主要说明：这次操作会改变或保留什么。
4. 次要说明：之后由系统还是用户控制。
5. 操作区：取消在前，明确的确认动作在后。

正文不使用参数表、额外卡片、分割线或宣传性措辞。启用时明确告知会替换材质、模糊、遮罩与背景；禁用时明确告知保留现值。主按钮用「启用默认设置」或「保留并手动调整」，不用含义不明的「好的」。

## 几何与排版

| 部位 | 当前值 | 目的 |
| --- | --- | --- |
| 弹窗宽度 | `min(380px, 100vw - 40px)` | 保持紧凑，左右至少20px空间 |
| 最大高度 | `100dvh - 40px` | 给短视口留下边距，内容超出时可滚动 |
| 内边距 | 上28px、左右26px、下22px | 上方舒展，动作区收紧 |
| 外圆角 / 描边 | 26px / 1px | 连续、柔软的整体轮廓；实际为CSS圆角，并非系统超椭圆 |
| 图标容器 | 46×46px，14px圆角，下间距18px | 小而明确的视觉起点 |
| 图标 | 24×24px SVG，1.5px描边，旋钮3px，圆线帽 | 不受字体回退影响 |
| 标题 | 19px、650字重、1.4行高、字距−.025em，下间距12px | 比旧版15px标题更有层级 |
| 主说明 | 13px、1.75行高 | 易读，不压成密集小字 |
| 次说明 | 12px、继承1.75行高，上间距10px | 次级信息有停顿但不抢标题 |
| 操作区 | 上间距24px，列宽1:1.4，间距10px | 主操作文案获得更多空间 |
| 按钮 | 最小高度42px，内边距10px 12px，13px圆角 | 有足够触按面积而不笨重 |
| 按钮文字 | 13px、550字重、1.4行高 | 与正文协调，靠结构区分功能 |

全体文字居中，沿用 `--sans`；主要内容用 `--ink`，次说明用 `--muted`。正文使用 `text-wrap: pretty` 改善尾行，但允许浏览器正常换行，不用 nowrap 强行挤宽。

视口宽度≤380px时，内边距变为24px 20px 20px，按钮改为单列，顺序仍是取消、确认。没有单独的手机DOM或横向滚动。

## 材质与颜色

基底是 `--paper`、`--ink`、`--line`、`--accent`，不另建一套品牌色。模态层为保证可读性使用固定的确认材质，不绑定导航/内容/下拉模糊滑条。

| 状态 | 背景与描边 | 层次 |
| --- | --- | --- |
| 纸媒 | 不透明 `--paper`，`--line` 描边 | `0 24px 70px rgb(0 0 0 / .2)` 阴影，无背景滤镜 |
| 现代通用 / 深色 | `--paper` 86%与透明混合，`--ink` 14%描边 | 28px背景模糊、135%饱和度；1px白色14%内高光；24px/70px黑色24%外阴影 |
| 现代浅色 | `rgb(250 250 248 / .68)`，白色65%描边 | 1px白色80%内高光；`0 22px 64px rgb(24 32 44 / .18)` 外阴影；保留相同28px模糊/135%饱和度，降低白色遮盖以显露环境色 |
| 遮罩 | `rgb(8 12 20 / .22)` | 轻压背景，不使用整屏强模糊 |

较高的不透明度是有意选择：背景只贡献环境色，不能透出干扰说明文字的清晰细节。内高光暗示表面受光，不使用发光边框或流动光斑。

图标底色为 `--ink` 4%与透明混合，边框用 `--line`。取消按钮底色由 `--ink` 5%升到悬停9%；确认按钮底色由 `--accent` 22%与纸色混合，悬停升到32%，描边为强调色40%。两者文字均为 `--ink`，不是白字渐变按钮。

## 动效：出现从容，离开利落

| 过程 | 起止状态 | 时长 / 缓动 |
| --- | --- | --- |
| 弹窗入场 | opacity 0→1；Y 8px→0；scale .96→1 | 420ms / `--ease-settle` |
| 弹窗退场 | opacity 1→0；Y 0→6px；scale 1→.97 | 160ms / `--ease-exit` |
| 遮罩入场 | opacity 0→1 | 320ms / `--ease-exit`（当前实现） |
| 遮罩退场 | opacity 1→0 | 160ms / `--ease-exit` |
| 按钮悬停 | 背景色浓度变化 | 180ms / `--ease-fluid` |
| 按钮按下 / 松开 | scale 1↔.975 | 160ms / `--ease-settle` |

当前全局有效曲线：settle=`cubic-bezier(.2,.82,.22,1)`；exit=`cubic-bezier(.4,0,.85,.25)`；fluid=`cubic-bezier(.16,1,.3,1)`。复用token，不在弹窗内复制曲线。

位移和缩放很小，没有过冲、摇晃或弹簧反弹。「更有活力」来自入场落位与触按回应，不是让用户等动画。

技术上用 `[open]`、`@starting-style` 和 `display/overlay allow-discrete`，让原生dialog在退场完成前保留绘制层。没有JS动画计时器，也不把业务确认延迟到动画结束。不支持这些CSS能力时允许直接显示/关闭，不能损害确认行为。

## 交互、安全与无障碍

- `showModal()` 使用浏览器顶层和模态焦点约束；不是在阅读面板里用z-index堆出弹窗。
- `aria-labelledby` 指向标题，`aria-describedby` 指向主要说明；SVG纯装饰，`aria-hidden`。
- 初始焦点为取消按钮，避免回车意外替换用户设置。保留可见焦点描边：2px强调色、3px偏移。
- 取消与Esc不改变外观值；只有确认才应用。保留原有原生dialog焦点恢复机制，不另加遮罩点击确认。
- `pendingDefaultSettings` 是待确认业务值；`dialogDefaultSettings` 是展示快照。关闭后清pending，但保持快照，避免退场标题从启用闪成禁用。
- `prefers-reduced-motion: reduce` 将相关过渡压至.01ms并去掉变形；`prefers-reduced-transparency: reduce` 使用实底、关闭背景滤镜。浏览器不支持该透明度媒体查询时维持默认材质。
- 本次没有改默认值、迁移、新老用户隔离、设置持久化或受管控件归属。

## 与原有 Inkroam 的关系及复用边界

| 维度 | 长文 / 原有页面语言 | 此确认弹窗 |
| --- | --- | --- |
| 注意力 | 保持阅读连续性 | 短暂集中到一次决定 |
| 排版 | 编辑式留白、正文主导 | 居中、紧凑、明确动作区 |
| 层次 | 页面内的柔和材质 | 遮罩、顶层表面、内高光 |
| 动效 | 阅读和导航的连续位移 | 微缩放落位与按压反馈 |
| 使用时长 | 长时间停留 | 几秒内理解并选择 |

可以把材质、按钮反馈与慢入快出的节奏复用到真正需要确认的模态窗口；不要把每张文章卡片、搜索结果或普通提示都改成这种居中玻璃面板。新组件仍需复用主题token、支持纸媒与减少动效，而不是为「像Apple」新增独立主题。

## 验证与后续验收

### 2026-09-26 截图复核与参数选择

用户提供浅色确认弹窗截图后，观察到背景已退后、弹窗呈蓝灰环境色、标题与按钮层级清晰。本轮建议保留现有材质，不再为了通透连续调低白底；这是单张静态截图的设计判断，不是动效或全主题验收。

当前实际代码：浅色白底不透明度 `.68`（32%透明）、背景模糊28px、背后中性暗色遮罩 `.22`。讨论中的 `.64～.72` 是调试范围，`.12` 遮罩只是建议，**没有实施**。Apple资料没有给出可直接映射到此CSS的最佳百分比，这些数值属于Inkroam自身的设计选择。

截图中两段说明尾行较碎，曾建议精简为「材质、模糊、遮罩与背景将采用当前模式的默认值。」与「随明暗模式自动调整。禁用后可恢复手动设置。」。本次仅记录建议，**未替换现有文案**，避免把讨论记成已实现。后续调整仍须保留启用替换现值、禁用保留现值的区别。

参数修改位置：`main.css` 的现代浅色 `.appearance-confirm` background 控制白底不透明度；现代通用 background 控制深色基底；`.appearance-confirm::backdrop` 控制页面遮罩。不要用整个弹窗的opacity调材质，它同时影响文字且参与入退场动画。

代码入口：`AppearancePanel.vue` 中的 `requestDefaultSettings` / `closeDefaultSettingsConfirm` / `confirmDefaultSettings` 与 `.appearance-confirm` 样式。测试入口：`scripts/check-reading-appearance.mjs`。

当前类型检查、15组源码/逻辑回归及新增弹窗契约通过；不等同于实机渲染、动画帧率或可读性验收。浏览器连接失败，尚待检查：

- 浅/深现代主题及纸媒下，文字、按钮焦点与复杂背景的对比。
- 启用/禁用、取消、Esc、再次打开时文案与焦点是否正确。
- 正常动效的进出连续性，确认导致换肤时是否有闪帧。
- 320px手机、横屏短视口、200%文字缩放时按钮与内容可达。
- 减少动效/透明度以及不支持离散过渡浏览器的退化路径。
