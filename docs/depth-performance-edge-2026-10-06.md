# Edge 层次感性能隔离记录

日期：2026-10-06。使用已连接的用户 Edge 和本机 Nuxt 开发服务。

## 方法与限制

- 浏览器接口不提供 DevTools tracing。临时开发插件通过 UI 按钮运行测试并显示结果，测试后删除，不进入正式代码。
- 宽桌面视口：工具请求1440×900，页面实际报告1309×818 CSS px，DPR≈1.10（不能把请求值当实际视口）。深色、默认材质、初始层次关闭。
- 每组先回到顶部稳定1500ms，再两次往返 scrollTop=100/0；每方向采样1500ms的 requestAnimationFrame 回调间隔。包括宽度变化和随后亮度变化，也包含动画结束后的部分时间；不是纯动画区间或GPU耗时。
- CSS隔离只在诊断中短暂使用，测试结束恢复原depth属性及滚动位置。各组顺序执行，存在热身/温度/其它进程等干扰，不据单轮最大值判根因；rAF间隔不等于实际呈现帧率。

## 本次结论与下一步

- Edge连接和服务均实际可用，已完成上述14组诊断（每组两次往返）。但没有GPU型号/合成轨迹，不能据此确认硬件或具体绘制函数瓶颈。
- 至少三条导航光效路径独立保留时都仍有较高P95，因此不能再把大inset阴影、SVG或亮度过渡之一说成唯一已确认根因。
- 禁用opacity过渡增加了样本数量，但P95和尖峰未明显恢复；延迟动画不是已证实的解决方案。
- 真正定位需Edge DevTools Performance轨迹：固定窗口同页面开/关层次各录数次，并比较Layout/Paint/Raster/合成任务和动画区间。本工具未提供tracing，不能用rAF冒充它。若继续代码实验，应一次更换一条绘制路径并用相同对照验收，不继续堆分片或will-change。
- 临时插件已删除；未改生产视觉代码，depth/滚动和临时视口恢复。用户之前未认可的分片代码仍是原工作区状态，本轮未擅自撤销或提交。
