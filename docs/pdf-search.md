# PDF 文内搜索

## 两条阅读路径

- `PdfViewer.vue` 按浏览器内嵌能力选择原生 object 或自带阅读器，不按屏宽判断。
- 原生路径不变，查找由浏览器 PDF 阅读器负责；不额外加载 PDF.js 或另行提取文字。
- `PdfCanvasReader.vue` 的搜索图标展开局部搜索栏，输入后按回车或「查找」开始，上/下一个循环跳转匹配页并定位高亮。不拦截全局 Ctrl+F。

## 实现与性能边界

- 复用已打开的 PDFDocumentProxy，第一次查询逐页 getTextContent；每页后让出事件循环，显示已搜索页数。搜索期间计数是当前已发现数量。
- 成功提取的文字缓存在当前阅读器内，后续查询复用；关闭搜索或卸载即清理应用缓存。PDF.js 自身内部缓存仍由文档生命周期管理。
- 查询变化、关闭或卸载使搜索令牌失效：已开始的 PDF.js 提取可以结束，但旧结果不能写回，也不再继续提取后面的页。
- `pdf-search.ts` 做不区分大小写的普通子串匹配、NFKC 兼容规范化和空白合并，保留原文字偏移；跨文字片段匹配，换行作为空格。不是正则表达式，不自动猜测断词、阅读顺序或数学语义。
- 仅搜索开启且关键词非空时渲染当前页 TextLayer；采用同页 CSS viewport，高 DPI 画布与文字层分别使用设备像素和 CSS 像素。补齐 PDF.js 的旋转与 scale-round 规则；未引入整套 viewer 样式。
- 高亮通过 createTextNode / textContent 创建，不把 PDF 文本拼为 HTML。普通匹配半透明黄，当前匹配橙：这是白色 PDF 纸面的标记，不更改网页主题。只滚阅读器内部，不滚外层文章。
- 搜索栏复用阅读器按钮和主题变量，grid 高度展开/收起，尊重 reduced-motion；窄屏允许控件换行。

## 限制和验证

没有文字层的扫描页不能搜索；特殊编码、复杂公式、连字和阅读顺序可能影响提取。部分页提取失败会提示不完整，不使整份 PDF 无法阅读。搜索仅针对当前附件，没有 OCR、云端上传或站内 PDF 索引。

`check-pdf-search.mjs` 覆盖文字映射、跨片段/跨行、大小写、Unicode、缓存、跳转、取消旧查询、关闭和部分失败；`check-pdf-controls.mjs` 保留翻页/缩放/旋转回归。mock 检查不是浏览器几何验收。

本轮浏览器工具返回空 apps/browsers，尚需实机复核：桌面/手机、两套主题的搜索栏；不同旋转角和缩放、设备像素比下高亮位置；大 PDF 连续换查询和关闭搜索。原生支持浏览器请确认仍使用原生查找。

自动化验收：typecheck 通过；以 BASE_PATH=/inkroam/ 静态生成成功；check --built 为 28/28。构建中 Nuxt 性能计时出现重复 console.time 标签警告，生成进程退出码为 0；不把它解释为 PDF 搜索错误。
