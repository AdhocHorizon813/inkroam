# 选段分享

2026-10-02。入口仍是文章/笔记页尾的 `CopyArticleLink`，不新增悬浮工具条、控件或CSS。

- 未选文字：原「复制本文链接」，去除查询参数和hash。
- 选中正文：文案变为「复制选段链接」，生成 `?passage=v1-…#所在章节`。定位粒度是整段，不是逐字高亮；复制时反馈实际复制了选段、章节还是全文。
- 只接受同一正文范围内的单个选区。无公式且唯一的单个段落/列表项可精确定位到块；跨段、包含KaTeX/MathML、代码、表格或重复文本时退章节；开篇没有章节则退全文。
- 指纹来自完整块文本的NFC/空白规范化，使用非加密哈希加长度。链接不含选区原文、搜索词或跟踪参数；指纹不是秘密或安全凭据。正文改写后标识可能失效，正常章节hash作为兜底。
- 不走浏览器原生Text Fragment高亮，而由站内路由配合现有文档/独立滚动容器定位；复用 `--anchor-offset` 与现有平滑/减少动效设置，不改页面入场动画。无需浏览器特有的精确文本分享API，也不向DOM插入选区HTML。
- `passage-scroll.ts` 只定位当前路由对应的文章，等待最多1.2秒；找不到/不唯一则回章节。等待期间URL变化即放弃，避免旧导航影响新页面；普通历史恢复不主动重定位选段。
- JavaScript禁用时保留普通章节锚点。正文删除、标题同时改名等情况无法保证旧链接定位；不会凭相似文字猜测目标。
- `selectionchange` 更新按钮状态，pointerdown保存按钮点击前的选区，避免点击导致选区折叠；快照只消费一次，卸载移除监听。自动复制失败仍沿用原手动输入框。应在选中文字后保留选区，滚动到页尾点击；移动端实际长按/滚动选区保留行为仍需实机验证。

实现：`utils/passage-link.ts`（选择/标识/URL）、`utils/passage-scroll.ts`（落点）、`router.options.ts`、`CopyArticleLink.vue`。文章仅增加不可见的 `data-article-path` 以避免误选仍在卸载的旧正文。

自动验证：`check-passage-link.mjs` 覆盖中文、Unicode/空白、选区边界、重复/公式兜底、干净URL、两种滚动坐标及导航失效；`check-copy-link.mjs` 覆盖捕获快照、章节/全文与剪贴板降级。测试使用DOM替身，不等同浏览器验收。浏览器工具本轮不可用，手机选区与最终视口位置尚待实测。
