# 阅读线索试点：说明为什么值得接着读

2026-10-06。落实设计提案中的内容关系方向，不重新装修已冻结的导航。

## 范围

数据结构02、08、09三篇笔记先试用。保留原文、课程前后篇、话题推荐、目录和路由动效。只在原有文末课程导航中补充作者明确维护的理由，不根据标签推导前置知识。

- `review`显示“需要时回顾”，是阅读建议，不宣称必须修完的先修课。
- `next`显示“接着探索”，不等于课程顺序中的下一讲。
- 如果关系目标就是原上一/下一篇，理由合入该入口；否则使用无新卡片材质的文字列表。
- 无字段、无有效目标时不渲染额外区域，保持旧体验。

## 编写方式

在笔记frontmatter中添加可选`readingLinks`，最多三条。例如以下JSON流式数组也是合法YAML：

```yaml
readingLinks: [
  { "path": "/notes/data-structures/01-pointers-and-ownership", "kind": "review", "reason": "回顾函数参数副本与调用者变量的区别。" }
]
```

请保持该流式数组格式，当前内容审计脚本据此解析配置。字段由content.config.ts的schema验证；理由1–160字符，真实标题从目标内容取得，不复制保存。链接填写不含`/inkroam`部署前缀的规范站内路径，交给NuxtLink处理baseURL。

第一版仅支持同课程、已发布笔记；不支持外链、锚点、查询参数或跨课程推荐。数据缺失、草稿、自链、重复、非法关系在展示层安全忽略；课程查询复用原有摘要，不新增请求，不把关系加进entrySummaryFields。公开笔记被删除或改为草稿时，应同时维护引用它的关系。
