## 1. 先从你做过的手机价格分类开始

### 1.1 模型是什么

在你的手机分类项目里，输入是电池容量、内存等特征，输出是手机的价格类别。

可以写成：

$$
\widehat y=f_\theta(x).
$$

这里三个符号分别表示：

- `x`：输入数据，例如一部手机的各项参数。
- `f`：模型使用的计算过程，例如一个多层神经网络。
- `θ`：模型中可以调整的全部参数，例如各层的权重和偏置。

帽子符号 `ŷ` 表示模型给出的预测。它可能与真实类别 y 不同。

**模型结构决定怎样计算，模型参数决定具体算出什么。**

### 1.2 训练在做什么

你已有一批手机数据，每部手机都有正确类别。模型先预测，再根据预测和正确类别计算损失。

损失可以理解为一个衡量预测好坏的数。具体用哪种损失，要看任务；你在分类项目中用过交叉熵。

训练过程是：

```text
输入数据和正确标签
    ↓
模型计算预测
    ↓
计算损失
    ↓
求损失对参数的梯度
    ↓
更新参数
    ↓
处理下一批数据
```

这里要分清两个操作：

```python
loss.backward()   # 计算梯度
optimizer.step()  # 使用梯度更新参数
```

反向传播负责高效计算梯度；优化器决定怎样使用这些梯度，例如普通梯度下降或 Adam。

### 1.3 为什么更新参数能够改变模型

用只有一个参数的函数举例：

$$
L(\theta)=(\theta-3)^2.
$$

要减小 L，就可以沿导数的反方向调整 θ：

$$
\theta\leftarrow\theta-\alpha\frac{\mathrm dL}{\mathrm d\theta}.
$$

α 是学习率，控制每次调整多少。神经网络参数很多，使用的是同样的求导和更新思路，只是导数变成了梯度向量。

到这里，我们还在讨论**有监督学习**：训练数据直接提供了希望模型预测的标签。

## 2. 从分类模型，走到语言模型

### 2.1 语言模型输出什么

分类模型可以输出“属于四个价格类别的概率”。语言模型也会输出概率，只是候选项变成了词表里的 token。

**Token 是处理文本时使用的基本单位。**它可能是一个字、一个词的一部分或一个符号，不能统一理解成一个汉字。

例如模型已经看到：

```text
中国的首都是
```

接下来会给不同 token 分配概率，再按照某种生成规则选择一个。生成之后，把新 token 加入已有文本，继续预测下一个。

```text
已有文本 → 下一个 token 的概率 → 选一个 token → 接到文本后面 → 再预测
```

重复这个过程，就能生成完整回答。

### 2.2 Softmax 在这里做什么

你学过的 Softmax，负责把一组原始分数转换为和为 1 的概率。

假设模型输出四个数 z_A、z_B、z_C、z_D，那么：

$$
p_j=\frac{e^{z_j}}{e^{z_A}+e^{z_B}+e^{z_C}+e^{z_D}}.
$$

这些原始分数常被叫作 **logits**。你可以把它们理解为模型的偏好分数；Softmax 将偏好分数转换为选择概率。

后面的教学模型只使用四个回答。它与大语言模型的规模差别很大，但能让我们看清“参数改变 → 回答概率改变”这件事。

### 2.3 问题、回答和参数的记号

后文采用以下记号：

| 符号 | 含义 | 例子 |
|---|---|---|
| x | 输入的问题，也常叫 prompt | “写一个求三个数最大值的函数” |
| y | 模型生成的完整回答 | 一段 Python 代码 |
| θ | 模型的参数 | 神经网络权重 |
| π_θ(y\|x) | 参数为 θ 时，面对问题 x 生成回答 y 的概率 | 某段代码被生成的概率 |

π 是希腊字母 pi。这里使用它，是因为强化学习中常用 π 表示“策略”。

**策略就是：面对当前输入，如何给不同选择分配概率。**在我们先研究的单题回答场景中，模型生成回答的概率分布就是策略。

## 3. 大模型的几种训练方式，先分清楚

### 3.1 预训练：学习预测文本

语言模型的一种常见预训练方式，是根据前面的文本预测后面的 token。

例如已有文本为“今天的天气很”，训练材料中的下一个 token 提供了学习目标。经过大量这样的预测任务，模型学到语言、知识及各种文本规律。

这一步仍然有可以直接比较的目标 token。

### 3.2 有监督微调：学习示范回答

**SFT** 是 Supervised Fine-Tuning 的缩写，中文通常叫有监督微调。

可以准备这样的数据：

```text
问题：写一个求三个数最大值的函数。
示范回答：
def largest(a, b, c):
    return max(a, b, c)
```

训练时，让模型提高生成示范回答中那些 token 的概率。

它和手机分类的联系是：都由数据提供学习目标。区别在于，语言模型的输出是一串 token，而非单个价格类别。

### 3.3 根据奖励训练：让模型尝试，再评价结果

另一个办法是让模型先自己生成回答，再运行程序评价它。

```text
给模型问题
    ↓
模型自己尝试回答
    ↓
判卷程序评价回答
    ↓
根据得分更新模型
```

判卷程序给出的数字称为**奖励（reward）**。例如代码通过检查得 1 分，没有通过得 0 分。

这给了模型探索不同回答的机会。一个任务可能存在很多正确解法，不必只围绕某一份示范回答学习。

本文要研究的是这种训练方式中的反馈问题：**奖励能否准确地告诉模型，什么回答值得学习。**

预训练、SFT、根据奖励训练可以组合使用；它们不是每个模型都必须依次经历的固定流程。

## 4. 强化学习到底是什么意思

### 4.1 最基本的几个角色

强化学习可以先理解为：一个能够作出选择的系统，根据选择带来的结果，调整以后作出选择的方式。

| 名称 | 普通解释 | 在回答问题的例子中 |
|---|---|---|
| 智能体 Agent | 作出选择的系统 | 语言模型，或包含语言模型的系统 |
| 动作 Action | 作出的选择 | 生成一个 token；在简化模型中，也可以把完整回答视为一次动作 |
| 环境 Environment | 选择发生并得到反馈的场景 | 题目、代码执行器等组成的任务环境 |
| 奖励 Reward | 评价结果的数值反馈 | 通过检查为 1，否则为 0 |
| 策略 Policy | 作出各个选择的概率规则 | 模型的回答概率分布 |

一般强化学习可以有很多步：先作出动作，环境变化，再作出下一个动作，最后才得到奖励。

为了入门，我们先研究更简单的情况：**给一道题，生成一次完整回答，获得一次奖励。**这可以作为一个单步决策问题来建模，不需要立刻处理所有多步强化学习概念。

### 4.2 Reasoning RL 和 Agent RL 分别是什么

这两个名称描述了不同的任务侧重点：

- **Reasoning RL**：用强化学习训练模型完成数学、代码等推理任务。本文主要围绕这类问题展开。
- **Agent RL**：用强化学习训练智能体在多步环境中行动，例如读文件、调用工具、执行代码，再根据结果决定下一步。

一个系统能够调用工具，不代表它一定经过了强化学习训练。判断时要看它究竟怎样更新参数，而不是只看它表现得像不像“智能体”。

### 4.3 什么是一次 rollout

后面论文经常出现 **rollout** 这个词。

在单次回答场景里，你可以把它理解为：**模型实际生成并完成一次回答的过程及记录。**

在多步 Agent 场景中，它通常包含从开始到结束的状态、动作和反馈序列，也常叫一条轨迹。

“生成 8 个 rollout”在本文的入门场景里，就先理解成“实际尝试生成 8 份回答”。这些回答可能重复。

## 5. 怎样把“得分”变成参数更新

### 5.1 先只保留四个候选回答

题目是：

> 输入三个整数 a、b、c，返回它们的最大值。

为了手算，假设模型只能从以下四段代码中选择：

为便于一起运行和比较，本文给四个函数使用不同名字。

```python
# 回答 A
def answer_A(a, b, c):
    return max(a, b, c)

# 回答 B
def answer_B(a, b, c):
    return max(a, b)  # 漏掉了 c

# 回答 C
def answer_C(a, b, c):
    return min(a, b, c)

# 回答 D
def answer_D(a, b, c):
    return 0
```

四个候选中，A 满足任务要求。B、C、D 都可以找到反例，因此不满足完整要求。

假设模型选择 A、B、C、D 的概率分别是：

```text
0.2，0.4，0.2，0.2
```

这里的概率由模型参数决定，并不是我们每一步直接指定它应该选哪个答案。

### 5.2 训练目标是平均获得多少分

设四个回答的分数为 r_A、r_B、r_C、r_D。它们的平均得分，即期望奖励，为：

$$
J=p_A r_A+p_B r_B+p_C r_C+p_D r_D.
$$

这个式子只是你学过的离散随机变量期望：每个结果的数值乘上出现概率，再相加。

如果判卷完全准确，只有 A 得 1 分，那么：

$$
J=p_A.
$$

训练就是调整参数，让这个 J 尽量大。你熟悉最小化损失的写法，也可以令损失 `L=−J`。

### 5.3 为什么需要“策略梯度”

对四个回答，我们能直接算出完整期望，然后求导。

真实语言模型可能生成的回答极多，通常无法将它们逐个列出来计算期望。因此，需要根据实际采样到的回答，估计该怎样更新参数。

**策略梯度（policy gradient）**研究的就是：怎样根据奖励，计算或估计策略参数的更新方向。

一个最简单的更新形式是：

$$
\text{奖励}\times\nabla_\theta\log\pi_\theta(y\mid x).
$$

先按中文读它：

> 根据这份回答拿到的奖励，给“提高这份回答生成概率”的方向分配权重。

这里对模型的对数概率求导，不要求判卷程序本身可微。完整等式的推导放在附录 A。

### 5.4 奖励为零，就一定在惩罚错误回答吗

在刚才最简单的“奖励乘以梯度”形式中，如果奖励为 0，这个样本对应的项就是 0。

要出现显式的负权重，一个常见办法是减去参考分数。下一节的“优势”就是沿着这条思路理解的。

## 6. GRPO：为什么将同一道题的多个回答放在一起

**GRPO** 是 Group Relative Policy Optimization 的缩写，可以译成“组相对策略优化”。它由 DeepSeekMath 提出，使用同一问题的一组回答来构造相对评价信号。原方法还有限制更新幅度等机制；我们先理解其中的组内比较。[原论文 §4.1](https://arxiv.org/html/2402.03300v3#S4.SS1)

### 6.1 一组回答是什么

对同一道题生成 G 份回答，分别判卷，得到 G 个分数。

```text
同一道题
  ├─ 回答 1 → 分数 r₁
  ├─ 回答 2 → 分数 r₂
  ├─ 回答 3 → 分数 r₃
  └─ 回答 4 → 分数 r₄
```

G 表示组大小。实际采样可能生成重复回答。为了便于手算，下面固定一组恰好包含 A、B、C、D 的回答。

### 6.2 先减去组内平均分

假设这组回答的真实分数是：

```text
[1, 0, 0, 0]
```

平均分是：

$$
\overline r=\frac{1+0+0+0}{4}=0.25.
$$

各自减去平均分：

```text
[0.75, -0.25, -0.25, -0.25]
```

这一步把“是否得分”变成了“比同组平均水平好多少”。

### 6.3 再除以标准差

标准差衡量这组分数有多分散。本文的手算统一使用：

$$
\sigma=\sqrt{\frac{1}{G}\sum_{i=1}^{G}(r_i-\overline r)^2}.
$$

组内标准化后的评价叫作**优势（advantage）**，记为 A_i：

$$
A_i=\frac{r_i-\overline r}{\sigma+\varepsilon}.
$$

ε 是防止除以零的小正数。不同实现可能在标准差约定等细节上不同；本文只使用上面明确写出的版本。

对于 `[1,0,0,0]`，标准差约为 0.433。手算时忽略 ε，就得到：

```text
[1.732, -0.577, -0.577, -0.577]
```

可以先把优势理解为：

- 正值：这份回答比同组平均表现好，给它正向的学习权重。
- 负值：它比同组平均表现差，给它反向的学习权重。
- 零值：这一项不提供相对优劣信号。

模型共享参数，一次更新会同时影响许多回答，所以不能将其理解成每份回答概率都有独立、绝对的升降保证。

### 6.4 优势怎样进入训练

先看一个简化的组相对训练损失：

$$
L(\theta)=-\frac1G\sum_{i=1}^{G}A_i\log\pi_\theta(y_i\mid x).
$$

在这一步求导中，A_i 作为已经算好的常数。

按降低 L 的方向更新参数，会倾向于提高正优势回答的对数概率，并降低负优势回答的对数概率。

**这个式子用于解释学习信号，不是完整 GRPO 目标。**完整方法还涉及采样时的旧策略、概率比值、裁剪等操作。裁剪可以先理解为限制某些更新的影响；现在不需要展开其公式。

### 6.5 为什么全是 0 分的一组没有相对信号

如果四份回答的分数都是 0，那么每份回答减去平均分后还是 0，优势也全为 0。

这组分数没有告诉模型，四份失败回答中哪一份更值得鼓励。全是 1 分时也存在类似的相对评价问题。

这不表示任务已经不值得学，而是说明这种组内信号在该组上无法区分优劣。

## 7. RLVR：分数由什么产生

**RLVR** 是 Reinforcement Learning with Verifiable Rewards 的缩写，通常译为“使用可验证奖励的强化学习”。可以先理解为：用能够运行的检查程序给模型的回答打分，再根据分数训练。

例如：

| 任务 | 一种可能的检查方式 |
|---|---|
| 数值计算 | 比较模型输出与已知答案 |
| 代码生成 | 运行测试用例 |
| 形式化证明 | 让证明检查器核查提交的证明 |

负责检查并给出结果的程序或系统，叫作**验证器（verifier）**。前文的“判卷程序”就是它。

“可验证”描述了反馈的产生方式，不意味着任何具体检查器都不会犯错。关于不完美验证器和奖励校正，已有专门研究。[相关论文](https://arxiv.org/abs/2510.00915v5)

### 7.1 用求最大值的例子检查一次

如果弱检查器只检查：

```python
answer_A(7, 3, 2)  # 返回 7，通过
answer_B(7, 3, 2)  # 也返回 7，通过
```

那么 A 和 B 都会通过。因为在这个输入里，忽略 c 也刚好得到了正确输出。

但再加一条检查：

```python
answer_A(2, 3, 7)  # 返回 7，通过
answer_B(2, 3, 7)  # 返回 3，失败
```

B 就会失败，因为它只计算前两个数的最大值。

因此，在这组固定候选里：

```text
完整要求对应的真实标签：[1, 0, 0, 0]
仅运行弱检查得到的标签：[1, 1, 0, 0]
```

我们可以人工判断这四段很简单的程序。现实中的复杂程序则更难判断；增加测试能够发现更多问题，但一般不能仅凭有限测试就证明任意程序完全正确。

### 7.2 一次误判怎样影响整个组

回到上一节的手算：

| 情况 | 分数 | 平均分 | 标准化后的优势，忽略 ε |
|---|---|---:|---|
| 按真实对错判卷 | `[1,0,0,0]` | 0.25 | `[1.732,-0.577,-0.577,-0.577]` |
| 把 B 也误判为正确 | `[1,1,0,0]` | 0.50 | `[1,1,-1,-1]` |

B 得到了正向权重；其他回答的权重也改变了。原因是它们共同使用这一组的平均分和标准差。

**这是整组估计问题出现的地方：一份回答的标签会影响多份回答的训练权重。**

## 8. 为什么通过率上升，真正正确率可能下降

### 8.1 两个比例先分开

仍然假设只有 A 真正正确，弱检查器接受 A 和 B。

- **真正正确率**：模型生成真正正确回答的概率，在这里是 p_A。
- **弱检查通过率**：模型生成能通过弱检查的回答的概率，在这里是 p_A+p_B。

“错误通过率”在本文中专门指生成错误且通过检查的回答的概率，这里是 p_B。

另一个可能使用的指标是“所有通过回答中，有多少是错误的”，即 `p_B/(p_A+p_B)`。它与 p_B 不是同一个比例，后面做实验时要写清楚分母。

### 8.2 已运行的小实验

我们先前运行过一个只训练四个 logits 的教学模型。Softmax 将它们转换为 A、B、C、D 的选择概率。

它能枚举四个候选，直接计算期望奖励和精确梯度。没有生成语言文本，没有调用代码检查器，也没有实现完整 GRPO。

两组实验的初始概率相同：

```text
p_A=0.2，p_B=0.4，p_C=0.2，p_D=0.2
```

一组使用准确奖励 `[1,0,0,0]`；另一组使用弱检查奖励 `[1,1,0,0]`。都更新 200 次，学习率均为 0.5。

| 状态 | 真正正确率 p_A | 弱检查通过率 p_A+p_B |
|---|---:|---:|
| 训练前 | 20.00% | 60.00% |
| 准确判卷训练后 | 99.16% | 99.47% |
| 弱判卷训练后 | 4.68% | 99.21% |

弱判卷训练提高了它实际优化的分数，但真正正确率下降了。

这里使用的检查规则和更新规则被明确固定。它说明这种失败可以发生，不意味着所有模型遇到误判都会产生相同结果。

![两种起点下的教学模型曲线](/images/notes/reinforcement-learning/from-model-training-to-research/reward_vs_correctness.png)

图中左侧的起点对 A、B 完全对称，二者最终概率也相同；右侧的起点更偏向 B，弱判卷训练进一步放大了这种偏向。两种起点都保留，是为了展示结论依赖哪些条件。

### 8.3 “奖励投机”是什么意思

通常把模型获得了高奖励、却没有按预期完成任务的现象称为 reward hacking，中文常译为奖励投机或奖励劫持。

不需要假定模型有人的欺骗意图，也能发生这种现象。仅由优化目标与真实任务要求不一致，就可能产生它。

## 9. 引入“复核”，会多出哪些问题

现在增加一个更可靠的检查过程，例如更多测试、更严格的证明检查，或人工检查。

我们把使用这种额外信息来重新判断回答的过程称为**复核或审计（audit）**。

在研究模型中，可以假设弱检查便宜、额外复核昂贵。这是需要明确的成本设定，不能不经测量就认为所有实际任务都符合。

### 9.1 第一种限制：不能检查所有回答

例如模型生成了 100 份回答，预算只够额外检查 10 份。此时要决定：

- 随机选 10 份；
- 优先检查可疑回答；
- 优先检查对训练更新影响大的回答；
- 或者选择少数组，把组内回答全部检查。

这些只是待比较的策略名称，尚不能断言哪一种最好。

这里还要分清：生成 100 份回答和复核 10 份回答，花的是两类成本。报告中必须分别计数。

### 9.2 第二种限制：额外复核也可能出错

例如强检查比弱检查更可靠，但仍然会偶尔接受错误回答，或拒绝正确回答。

这时，“有复核结果”也不等于“已经得到无误的真值”。我们需要说明复核怎样出错。

本文后续候选研究的一个起点，是已知、独立的二元翻转错误：对的偶尔判成错，错的偶尔判成对。

这个简单模型便于起步，但现实 LLM 判卷器可能在相似内容上持续犯同类错误。不能把重复调用自动当作独立复核。

### 9.3 三种不同的错误，不要混在一起

| 情况 | 例子 | 需要注意什么 |
|---|---|---|
| 固定检查漏洞 | 漏测 c 为最大值的输入，B 总能蒙混过去 | 多运行同一个确定性测试没有新信息 |
| 独立随机误判 | 每次判卷独立地以给定概率翻转结果 | 重复复核可能提供额外信息，但要计成本 |
| 相关或系统性误判 | 同类错误推理反复被同一个 judge 接受 | 不能默认重复多数投票就能消除错误 |

上一节的小实验属于第一种。我们还没有据此验证后两种情形的训练效果。

## 10. 现在才能准确说出我们的论文候选

### 10.1 先用普通话表述

> 模型每道题会尝试多个回答。便宜的检查器会判错，额外复核又有成本，而且也可能判错。我们希望设计一种办法，在有限复核预算下，让用于训练的整组更新更接近依据真实标签计算出的更新，并证明误差能够控制到什么程度。

这里研究的是“反馈如何可靠地进入训练”。单独观察到奖励投机，或者简单增加一个检查器，都不是新贡献。

### 10.2 “整组更新”到底指什么

固定已经生成的一组回答，以及当前准备更新的模型参数。

如果拿到所有真实标签，我们可以按照事先指定的训练公式，算出一个更新向量。把它记为：

$$
g_{\text{完整标签}}.
$$

它是一长串数，分别对应参数应该怎样调整。

现在只有部分、可能带噪的复核结果，我们算出另一个向量：

$$
\widehat g.
$$

帽子表示估计。一个可以研究的量是：

$$
\mathbb E\left[\left\|\widehat g-g_{\text{完整标签}}\right\|^2\right].
$$

按中文读：**在复核和抽样的不确定性下，我们算出的更新，与完整标签更新相差多少。**

这比“模型最终会不会变聪明”范围更小，适合先定义清楚并尝试证明。

### 10.3 要区分两个目标

“估计出了完整标签下的 GRPO 更新”与“估计出了真正正确率的梯度”，是两个不同的数学陈述。

GRPO 有组内标准化等结构。即使标签全部正确，它的指定更新也不能不加条件地等同于真正正确率的无偏梯度。

因此候选论文需要先选定目标，再证明针对该目标的结果。不能在推导中悄悄换目标。

### 10.4 为什么不直接把每个分数纠正一下

因为后面还要计算组平均、标准差，可能还要进行裁剪。这些操作会共同依赖整组标签。

一个分数估计量长期平均准确，不意味着把它代入所有后续运算之后，得到的更新也长期平均准确。附录 C 用两份回答给出一个能手算的例子。

### 10.5 怎样才算做出了论文贡献

可以争取下面几种成果中的明确组合：

| 成果 | 普通解释 |
|---|---|
| 新算法 | 给出实际可执行的复核对象选择和更新计算办法 |
| 误差上界 | 证明该办法最多有多大误差，依赖多少预算和哪些假设 |
| 必要成本下界 | 证明在同样的信息条件下，任何算法都无法无限节省复核成本 |
| 有意义的实验 | 在匹配成本的强基线下检验收益，同时保留失效情形 |

目前已经知道：线性奖励噪声校正已有研究；精确标签下，固定组的审计复杂度也有[直接相关的公开手稿](https://github.com/Bubu631/agent-audit-complexity)。

所以“把这些已有工具组合一下”不自动形成贡献。我们还需要找到带噪、有限预算和组内非线性共同造成的具体困难，并确认已有理论没有直接解决它。

本项目目前尚未完成这一步。更详细的边界保存在[切口筛选报告](/downloads/notes/reinforcement-learning/from-model-training-to-research/research/RESEARCH_CUTS_2026-11-01.md)，初读本文时可以暂不打开。

## 11. 你现在从哪里开始，才不会一下跳到论文术语

### 第一步：理解一个按奖励更新的四选项模型

你已经具备阅读这个例子所需的编程起点。需要补的核心概念是：

1. 策略是选择概率。
2. 目标是提高期望奖励。
3. 策略梯度连接奖励与参数更新。

可以对照[四选项教学代码](/downloads/notes/reinforcement-learning/from-model-training-to-research/research/learning/01_reward_vs_correctness.py)与[第一课的代码说明](/downloads/notes/reinforcement-learning/from-model-training-to-research/research/learning/01_README.md)。这里保存的实验已经运行过，不需要先下载语言模型。

这份脚本用 NumPy 写出显式梯度。它与 PyTorch 的自动求导对应的是同一类求导计算；只是四个参数足够简单，可以把计算全部展开。

### 第二步：读懂一组回答的学习信号

能够手算 `[1,0,0,0]` 和 `[1,1,0,0]` 的平均分、标准差和优势，就能看到“错误标签影响全组”的机制。

这一阶段再接触基线、标准化，以及为什么简单校正不一定保留后续更新。不要同时引入整个 PPO、Adam 收敛理论和大模型工程框架。

### 第三步：把一个研究问题定义清楚

例如明确规定：

```text
固定一组已经生成的回答。
真实标签只能是 0 或 1。
复核会以已知概率误判。
每个回答只允许复核一次。
目标是估计一个事先指定的组更新。
预算和误差的定义固定。
```

这是一个可以开始推导的数学模型。若允许重复独立复核，或把目标换成最终训练正确率，就已经是另外的问题，需要重新定义。

模型明确之后，才能准确比较最近论文有没有研究同一件事。

### 第四步：确认值得继续，再开展算法实验

先用可枚举的小环境检验推导和反例，再比较复核算法。算法值得继续时，才考虑小语言模型与实际任务。

比较时需要同时报告：真正正确率、检查通过率、复核成本和生成成本。还应保留无法认证、算法无效和假设不成立的设置。

小实验可以成为论文工作的起点，但只有清晰的新问题、实质结果和相应证据，才能构成我们要追求的论文产出。

### 另外两条候选，用一句话理解

| 候选 | 普通解释 |
|---|---|
| 当前优先：带噪复核与整组更新 | 少检查一些、检查又会出错时，怎样仍然算出足够可靠的训练更新？ |
| 审计复用 | 已经检查过的回答，能支持模型继续更新多久，何时必须补充新检查？ |
| 生成与复核双成本 | 同样一笔钱，应该多生成回答，还是更认真地检查已有回答？ |

当前先理解第一条，不要求同时展开三套研究。

## 附录 A：策略梯度怎样从求导得到

这一部分可以在读完正文后再看。先固定一道问题 x，假设只有有限多个候选回答，奖励不直接依赖模型参数 θ，且各候选的概率为正。

### A.1 写出目标

$$
J(\theta\mid x)=\sum_y\pi_\theta(y\mid x)r(x,y).
$$

求和遍历所有候选回答。r(x,y) 是问题 x 下，回答 y 得到的奖励。

### A.2 对参数求导

因为奖励在这里不直接依赖 θ：

$$
\nabla_\theta J=\sum_y r(x,y)\nabla_\theta\pi_\theta(y\mid x).
$$

利用对数函数的求导关系：

$$
\nabla_\theta\pi_\theta(y\mid x)
=\pi_\theta(y\mid x)\nabla_\theta\log\pi_\theta(y\mid x).
$$

代入得到：

$$
\nabla_\theta J
=\sum_y\pi_\theta(y\mid x)r(x,y)\nabla_\theta\log\pi_\theta(y\mid x)
=\mathbb E_{y\sim\pi_\theta(\cdot\mid x)}
\left[r(x,y)\nabla_\theta\log\pi_\theta(y\mid x)\right].
$$

因此，独立生成若干回答之后，可以用实际样本的平均值估计这个期望。

这里讲的是指定条件下的基础策略梯度恒等式。实际模型的长序列、不同采样分布和更新机制需要另外处理。

### A.3 为什么减去一个基线仍然可以成立

若 b(x) 对这次采样的回答 y 不变，则：

$$
\mathbb E_y\left[b(x)\nabla_\theta\log\pi_\theta(y\mid x)\right]
=b(x)\nabla_\theta\sum_y\pi_\theta(y\mid x)=0.
$$

所以将 r 替换成 `r−b(x)`，在这些条件下不改变期望梯度。这种参考值就叫**基线（baseline）**。

但若基线使用了当前同一组样本，便需要检查依赖关系。不能不经推导就把上式直接套过去。

例如，对 G 个独立同分布回答，使用包含样本自身的组均值作基线，在没有组标准差等后续操作时，期望更新会多出 `1−1/G` 的系数。若使用排除自身的其他样本均值，则满足另一种独立性关系。

这解释了为什么“减平均看起来一样”，在严格证明中也要检查到底减了哪个平均。

### A.4 四选项代码中的梯度

记 z_j 为第 j 个 logit，p_j 为 Softmax 概率。其导数为：

$$
\frac{\partial p_i}{\partial z_j}=p_i\left(\mathbf 1\{i=j\}-p_j\right).
$$

这里的指示符在 i=j 时为 1，否则为 0。由 `J=Σ_i p_i r_i` 可得：

$$
\frac{\partial J}{\partial z_j}=p_j(r_j-J).
$$

因此代码中的更新为：

```python
probs = softmax(logits)
average_reward = probs @ rewards
gradient = probs * (rewards - average_reward)
logits += learning_rate * gradient
```

这里减去的是根据完整四项概率算出的期望 J，不是某一批样本的随机组均值。它与 GRPO 组内标准化的具体更新不能混为一谈。

## 附录 B：读研究报告时常见的几个词

### B.1 无偏：平均对准目标

如果要估计某个真实量 g，估计结果记为 ĝ。无偏指：

$$
\mathbb E[\widehat g]=g.
$$

期望通常针对算法的抽样、复核随机性等取平均。它不表示某一次结果就准确。

例如真实量是 0，估计器以相同概率输出 100 或 −100。它无偏，但每次都相差很大。

### B.2 偏差：平均位置偏了多少

偏差定义为：

$$
\operatorname{Bias}(\widehat g)=\mathbb E[\widehat g]-g.
$$

这里的 g 可以是一个数，也可以是一组更新参数的向量。

### B.3 方差：估计结果有多不稳定

对向量，可以用下面这个标量衡量波动：

$$
\mathbb E\left[\left\|\widehat g-\mathbb E[\widehat g]\right\|^2\right].
$$

它衡量估计结果围绕自身平均值的分散程度。比较算法时，应说明使用什么范数和什么分布来计算。

### B.4 均方误差：总体偏离目标多少

$$
\operatorname{MSE}=\mathbb E\left[\left\|\widehat g-g\right\|^2\right].
$$

它可以分成：

$$
\operatorname{MSE}
=\left\|\mathbb E[\widehat g]-g\right\|^2
+\mathbb E\left[\left\|\widehat g-\mathbb E[\widehat g]\right\|^2\right].
$$

也就是“偏差平方 + 波动”。因此，允许一点偏差但大幅减少波动，可能降低均方误差；是否值得，要看具体任务与误差要求。

### B.5 上界和下界

- **算法的误差上界**：在假设成立时，证明某种方法的误差不超过一个量。
- **必要成本下界**：在明确的实例范围与信息访问条件下，证明任何方法都至少需要一定成本。

若算法的成本与必要下界接近，才能有根据地谈“接近最优”。只证明一个上界，还不知道是否存在便宜得多的算法。

### B.6 高概率保证

“以至少 95% 的概率，误差不超过 ε”与“平均误差比较小”是两种不同的结论。

前者关心越过误差门槛的风险，后者关心平均损失。做可靠更新时，可能需要前者，而不能只给一个平均值。

### B.7 硬预算和期望预算

假设一组有四份回答：

- 每次最多检查一份，叫硬上限为 1。
- 以 1/4 的概率检查全部四份，其余时候不检查，平均也只花一次检查成本。

两种方法的平均成本相同，但第二种有时会花四次，不能称为“每次最多一次”。整组更新问题中，这种区别可能决定算法是否可行。

## 附录 C：为什么分数无偏，代入标准化之后却可能有偏

这是一个说明障碍的标准小例子，不是本项目的新结果。

### C.1 准确标签下的目标

只有两份回答，真实分数为 `[1,0]`。

平均分为 0.5，按本文约定计算的标准差为 0.5。因此，标准化优势为：

```text
[1, -1]
```

### C.2 构造一个平均正确的分数估计

假设第二个分数已知为 0，第一个分数只能随机复核。以 1/2 的概率复核并发现其真实分数为 1。

构造估计：复核了就记成 2，没有复核就记成 0。

第一个分数估计的平均值为：

$$
\frac12\times2+\frac12\times0=1.
$$

所以两个分数估计的期望确实是 `[1,0]`。估计量可以大于 1，因为它在这里承担的是带权估计作用，而不是概率。

### C.3 先估分数，再标准化

只有两种情况：

| 概率 | 估计分数 | 标准化优势，忽略非零标准差时的 ε |
|---|---|---|
| 1/2 | `[2,0]` | `[1,-1]` |
| 1/2 | `[0,0]` | `[0,0]`，常数组约定为零 |

优势的平均值因此为：

```text
[0.5, -0.5]
```

它不等于根据真实分数直接算出的 `[1,-1]`。

原因就是：**先求平均再进行非线性运算，与先进行非线性运算再求平均，一般不能交换。**

从你熟悉的概率知识看，最简单的类似事实是：`E[X²]` 通常不等于 `(E[X])²`。

这说明“逐项分数估计无偏”还不足以解决整个训练更新的估计问题。
