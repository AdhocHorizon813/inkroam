## 这不是一组让你背答案的题

本讲补课程截图中“内部排序题目讲解”和“查找与排序大题”的训练环节。**以下全部为自编题，不是视频原题，也不是已核验年份、院校的真题。** 对应知识先看[查找与索引结构](/notes/data-structures/06-search-trees-and-hashing)与[排序及外部存储](/notes/data-structures/07-sorting-and-external-memory)。

读题时先写四行：输入对象是什么；输出到底是一个值、一个位置还是一个集合；允许修改输入吗；对时间和辅助空间有什么要求。对数学背景读者，最容易忽略的是第二、三行：数学上写“求交集”很自然，程序却必须决定重复值算几次、结果写在哪个数组、容量够不够。

解答按“朴素办法→利用结构改进→状态与不变量→代码→边界”展开。先不要跳到末尾长代码。前三道算法题共用一份完整C17程序，但每个函数可以分开读。

## 题一：有序数组中，一个值究竟出现了几次

输入非降序数组a，共n个整数，允许重复；给定key，返回其出现次数。不修改输入，要求O(log n)时间、O(1)辅助空间。n可为0。

### 为什么“找到一个，再左右扫描”不够

折半找到某个key后逐个向两侧扩展，在全部元素都相等时仍扫描n项，最坏O(n)。题目要求的是最坏对数时间，不能拿第一步使用了二分当作整个算法的复杂度。

有序性保证等于key的元素形成连续一段。定义L为第一个满足a[i]≥key的位置，R为第一个满足a[i]>key的位置；找不到满足项时返回n。于是[L,R)恰好是所有等于key的位置，数量为R−L。这是两个单调谓词的分界，而不是寻找两个“恰好等于”的记录。

样例a=[1,2,2,2,4,7]，key=2。下标从0开始，候选边界使用半开区间式收缩，初始lo=0、hi=n。

| 查找 | lo,hi | mid及值 | 更新依据 | 新lo,hi |
| --- | --- | --- | --- | --- |
| L | 0,6 | 3，值2 | 值≥2，答案在mid或更左 | 0,3 |
| L | 0,3 | 1，值2 | 值≥2 | 0,1 |
| L | 0,1 | 0，值1 | 值<2，该位置及左边都排除 | 1,1 |
| R | 0,6 | 3，值2 | 值≤2，该位置仍不够大 | 4,6 |
| R | 4,6 | 5，值7 | 值>2 | 4,5 |
| R | 4,5 | 4，值4 | 值>2 | 4,4 |

L=1、R=4，所以次数3。若查3，则两个边界都为4，差为0；若查8，两者都为6。位置n是合法的返回结果，但不是合法数组下标，不能直接读取a[n]。

### 不变量为什么足以证明答案

求L时始终有：所有下标小于lo的元素<key；所有下标不小于hi的元素≥key。中间未确定部分不断缩小，结束lo=hi后，这个位置就是两种性质的分界。求R把条件分别换成≤key和>key。注意hi=n时“从n开始的元素”是空集，不需要a[n]真的存在。

每轮候选宽度至少约减半，所以两次查找仍是O(log(n+1))，通常在n≥2时简记O(log n)。写mid=lo+(hi−lo)/2，避免直接lo+hi可能溢出。中点相等时，L向左收、R向右收，方向来自定义，不能凭记忆随意互换。

## 题二：两个有序表的交集，重复元素算一次

### 用最小的计数程序核对上一题的含义

设L是第一个不小于x的位置，R是第一个大于x的位置。在非降序数组中，所有等于x的下标恰是半开区间[L,R)，所以数量是R-L，而不是R-L+1。下面暂用线性扫描求边界，单独验证“边界转数量”这件事；后面的折半程序再把寻找边界加速到对数时间。

```c
#include <assert.h>
#include <stdio.h>
int main(void) {
    const int a[] = {1, 2, 2, 2, 4};
    for (int x = 2; x <= 3; ++x) {
        int l = 0, r = 0;
        while (l < 5 && a[l] < x) ++l;
        while (r < 5 && a[r] <= x) ++r;
        printf("x=%d: [%d,%d), count=%d\n", x, l, r, r-l);
        assert(r-l == (x == 2 ? 3 : 0));
    }
    return 0;
}
```

x=2时位置1、2、3共三个，R=4不包含在区间里；x=3时L=R=4，空区间正确给出0。定义本身已经统一“存在”和“不存在”，不用另造一个负数下标再参与减法。

输入两个非降序数组a、b，长度分别为m、n。输出同时出现于二者的不同整数，按升序，每个值只输出一次。不能修改输入，时间O(m+n)。调用者提供最多min(m,n)个位置的输出数组。

“集合交集”与“多重集交集”不同：a=[1,2,2,4,6]、b=[2,2,3,6,6]，本题结果为[2,6]，不是[2,2,6]。若题目想保留出现次数的最小值，算法在相等后跳过重复的规则就要改变。

### 两根手指分别指向尚未处理的位置

i指向a中尚未处理的第一个元素，j指向b中尚未处理的第一个元素，k是已经写入的结果数。它们不是三个关键字，只是下标与计数。

| 当前a[i],b[j] | 动作 | 为什么安全 |
| --- | --- | --- |
| 1,2 | i右移 | b剩余值都≥2，1不可能再找到相等项 |
| 2,2 | 输出2，两边分别越过整段2 | 2已记过一次，本题不保留重复 |
| 4,3 | j右移 | a剩余值都≥4，3不可能再匹配 |
| 4,6 | i右移 | b剩余值都≥6，4不可能再匹配 |
| 6,6 | 输出6，越过两边所有6 | 然后至少一侧耗尽，结束 |

不变量：输出区out[0,k)恰是已确定的交集部分，严格递增且无重复；已跳过的值都已输出或证明不可能再匹配。一次移动至少推进一个下标，二者总共最多前进m+n步，因此即使代码有内层“跳过相同值”循环，也不是O(mn)：每个输入位置全程最多跨过一次。

输出容量为何min(m,n)足够？每个不同输出值都必须在两个输入中各有至少一个位置，输出数不可能超过任一输入长度。这是容量证明，不代表函数会替你申请内存。若输出数组与输入重叠，写入可能破坏后续读取，本例明确禁止重叠。

## 题三：主元素不是“出现次数最多的那个”

输入任意顺序的整数数组，找出现次数**严格大于n/2**的值；若不存在则报告失败。不修改输入，要求O(n)时间、O(1)额外空间。这里的主元素是多数元素，不等于统计学中无需超过一半的众数。

a=[1,1,2,2,3]里1和2并列最多，但都不超过5/2，不存在主元素。主元素若存在则唯一：若有两个不同值各超过一半，总次数会超过n。

### 删去两个不同的值，候选为何还能保留

假设主元素x出现c次，c>n/2。删掉两个不同的值时，至多删掉一个x，剩余x至少c−1次，而新总数n−2的一半为n/2−1，因此仍严格占多数。若没有删到x，优势只会更大。

这是配对抵消的依据。程序并不真的删数组，而用candidate与votes模拟“尚未抵消的同值记录”。votes不等于candidate在整个前缀的总出现次数，只是抵消后的余额。

| 读入序列2,1,2,3,2,2,4 | candidate | votes | 动作含义 |
| --- | --- | --- | --- |
| 2 | 2 | 1 | 无余额，建立候选 |
| 1 | 2 | 0 | 与一个2配对抵消 |
| 2 | 2 | 1 | 重新建立候选 |
| 3 | 2 | 0 | 再抵消 |
| 2 | 2 | 1 | 重新建立候选 |
| 2 | 2 | 2 | 同值，余额增加 |
| 4 | 2 | 1 | 不同值，余额减一 |

第一遍只得到候选2。第二遍再数2实际出现4次，4>7/2，才成功。对[1,2,3]同样运行也会产生候选3，但只出现一次，必须验证后判失败。“可能留下一个数”不等于“证明这个数超过一半”。

C里n/2为整数除法；次数是整数，用count>n/2恰好表示严格过半，而且比2×count>n更能避免乘法溢出。空数组直接失败；失败时输出参数不变，调用者不能把原来的值当作结果。

## 完整 C17 程序：三个接口及边界测试

lower/upper返回位置；range_count返回次数；intersection返回写入out的个数；majority返回是否存在，只有成功才通过int *answer写出值。返回值与输出参数的职责不同，读函数时先看这一点。

数组长度必须真实，非空输入指针必须有效；交集输出应有足够容量且不与输入重叠；majority的answer必须有效。这里用assert帮助发现示例调用错误，不是可抵抗任意无效地址的安全库。

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdio.h>

size_t lower(const int a[], size_t n, int key) {
    size_t lo = 0, hi = n;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] < key) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}
size_t upper(const int a[], size_t n, int key) {
    size_t lo = 0, hi = n;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] <= key) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}
size_t range_count(const int a[], size_t n, int key) {
    return upper(a, n, key) - lower(a, n, key);
}
size_t intersection(const int a[], size_t m,
                    const int b[], size_t n, int out[]) {
    size_t i = 0, j = 0, k = 0;
    while (i < m && j < n) {
        if (a[i] < b[j]) ++i;
        else if (a[i] > b[j]) ++j;
        else {
            int value = a[i];
            out[k++] = value;
            while (i < m && a[i] == value) ++i;
            while (j < n && b[j] == value) ++j;
        }
    }
    return k;
}
bool majority(const int a[], size_t n, int *answer) {
    assert(answer != NULL);
    if (n == 0) return false;
    int candidate = 0;
    size_t votes = 0;
    for (size_t i = 0; i < n; ++i) {
        if (votes == 0) { candidate = a[i]; votes = 1; }
        else if (a[i] == candidate) ++votes;
        else --votes;
    }
    size_t count = 0;
    for (size_t i = 0; i < n; ++i)
        if (a[i] == candidate) ++count;
    if (count <= n / 2) return false;
    *answer = candidate;
    return true;
}

/* 测试工具：小数组插入排序，供边界查找使用有序输入。 */
void sort_small(int a[], size_t n) {
    for (size_t i = 1; i < n; ++i) {
        int value = a[i];
        size_t j = i;
        while (j > 0 && a[j - 1] > value) {
            a[j] = a[j - 1]; --j;
        }
        a[j] = value;
    }
}
int main(void) {
    int a[] = {1,2,2,4,6}, b[] = {2,2,3,6,6}, out[5];
    size_t k = intersection(a, 5, b, 5, out);
    assert(k == 2 && out[0] == 2 && out[1] == 6);
    assert(intersection(NULL, 0, b, 5, out) == 0);
    int c[] = {-3,-3}, d[] = {4,4};
    assert(intersection(c, 2, d, 2, out) == 0);
    assert(intersection(c, 2, c, 2, out) == 1 && out[0] == -3);
    assert(range_count(NULL, 0, 1) == 0);
    int answer = 99;
    assert(!majority(NULL, 0, &answer) && answer == 99);

    /* 枚举长度0..6、取值-1/0/1的全部1093个数组。 */
    size_t cases = 0;
    for (size_t n = 0, total = 1; n <= 6; ++n, total *= 3) {
        for (size_t mask = 0; mask < total; ++mask) {
            int raw[6], sorted[6];
            size_t code = mask;
            for (size_t i = 0; i < n; ++i) {
                raw[i] = (int)(code % 3) - 1;
                sorted[i] = raw[i]; code /= 3;
            }
            sort_small(sorted, n);
            bool expected = false;
            int expected_value = 0;
            for (int key = -2; key <= 2; ++key) {
                size_t count = 0;
                for (size_t i = 0; i < n; ++i)
                    if (raw[i] == key) ++count;
                assert(range_count(sorted, n, key) == count);
                if (count > n / 2) { expected = true; expected_value = key; }
            }
            answer = 99;
            bool found = majority(raw, n, &answer);
            assert(found == expected);
            if (found) assert(answer == expected_value);
            else assert(answer == 99);
            ++cases;
        }
    }
    assert(cases == 1093);
    puts("search/sort exercises: samples and 1093 small-array cases passed");
    return 0;
}
```

末尾枚举不是新的算法知识点：mask被反复除3、取余，生成由−1、0、1组成的全部短数组；朴素计数作为独立答案，与较快算法比较。它覆盖空输入、重复、全相同、恰好一半、无主元素等小规模状态，但不证明任意长数组都正确；证明仍依赖前面的不变量与抵消论证。交集此处使用定向样例，不把1093次都说成对交集的穷举。

## 题四：已知一个排序中间状态，能否认出算法

输入[3,1,2]，某趟后成为[1,2,3]，能否断言用冒泡？不能：向右冒泡第一趟得到[1,2,3]，直接插入第二趟也得到它，选择排序也可得到它。最终有序状态的信息尤其少。

严谨做法是根据题目指定的趟数、方向、枢轴选择与完整状态序列，逐个排除不可能项。第七讲已给同数组三种排序的前两趟。答题不要把“符合一种算法的不变量”写成“只有它可能做到”。例如尾部最大元素就位，是冒泡可能具有的特征，不是它的身份证。

若题目省略快速排序的分区规则，只给“以首元素为枢轴”，仍可能存在不同合法中间排列。能确定的是分区大小关系，不一定能唯一确定每个位置。手推题应先明确使用哪段伪代码。

## 题五：两个有序段归并，比较次数与稳定性分别怎么算

合并[1,4,7]和[2,3,8,9]，每次比较段首，取较小者：比较1/2取1；4/2取2；4/3取3；4/8取4；7/8取7。左段空，直接复制8、9，无须再比较关键字。因此实际5次比较，不是总长度减一必然等于6。

对两段非空、长度m和n，最坏m+n−1次比较，是直到只剩最后一个元素前两边都未空的情形；最好min(m,n)次，较短段可被连续取完。输出写入仍有m+n次，不能把“无需比较”误读成“复制免费”。

若段首键相同而左段记录在原输入中先出现，为保持稳定应先取左段。例左[2a,5]、右[2b,4]，应得到[2a,2b,4,5]。排序只比较键，a/b是观察稳定性的身份。若只用整数、不保留身份，运行结果本身无法展示相等记录是否互换。

## 题六：选算法之前，先问输出要什么

要求从n个元素中取最大k个：若只要这k个的集合，不必把全部n个排好序；若还要求k个按序输出，需要再处理这部分。大小k的小根堆把当前入选者中最小值放在根，新元素比根大才替换并下滤；根是门槛，不是全部输入最小值。

例如k=3，输入4、1、7、2、9：最初入选{1,4,7}，门槛1；读2替换1，变{2,4,7}，门槛2；读9替换2，变{4,7,9}。堆内部数组不必升序，最后若要输出4、7、9，需对入选结果排序。

维护阶段O(n log(k+1))时间、O(k)空间，之后排序k项O(k log k)。k=0直接空结果，k>n按题目规定报错或截为n，不能让这些边界落入“先取前k项”的越界读取。这里给思路与手推，不冒称上方程序包含堆式top-k实现。

## 自己写答案时的检查单

- 我是否写清重复值、空输入、端点包含关系和失败返回语义？
- 每个变量是否能用一句普通话说明，而不是“i就是i”？
- 我删除或跳过一段时，有没有说明它不可能包含未报告的答案？
- 内层循环是否跨轮重复工作，还是每个位置全程只被推进一次？
- 输出空间算不算辅助空间，是否与题目约定一致？
- 运行通过是测试证据，还是被我误写成数学证明？
