## 为什么先补这一课

数学证明通常允许你在同一页上同时看到所有已知条件；程序只能根据当前状态执行下一条语句。学算法的一个门槛，是把“这个结论显然成立”拆成“这一步读哪个旧值，写哪个新值，下一步还知道什么”。本讲不新增一堆结构名称，而是训练这套翻译能力。

建议先读第一讲对指针和值传递的解释，再读本讲，随后回到二叉树遍历。你不需要已经掌握AVL或最短路。

## 一、函数接口像命题，但还有执行副作用

假设函数的任务是计算数组前n项的和。一个完整约定至少包含：

- **前置条件**：n在允许范围内；当n大于0时，a指向至少n个可读整数；加法结果在所用类型范围内。
- **后置条件**：返回值等于这些输入整数之和；n为0时返回0。
- **副作用**：本例不修改数组，不分配动态内存。

“能编译”不代表满足前置条件。编译器能知道a的类型是指针，却通常不知道这个地址后面实际有几个元素。传入长度100并不会让一个三元素数组自动变长。

用逻辑记号可写成 $\{P\}\ C\ \{Q\}$：在P成立时执行程序C，若正常结束则Q成立。这是部分正确性。再证明它确实结束，才得到总正确性。这里不要求先学习形式化验证工具，但应养成区分两者的习惯。

## 二、递归调用不是“跳回函数开头并覆盖所有变量”

考虑定义 $S(n)=S(n-1)+a_{n-1}$，$S(0)=0$。调用S(3)时，并不是把外层的n永久改成2；程序为S(2)创建新的调用状态，保留外层尚未完成的“再加a[2]”任务。

设数组为2、-1、4：

| 阶段 | 当前调用 | 暂停等待的操作 | 已返回的值 |
| --- | --- | --- | --- |
| 下降 | S(3)调用S(2) | 加a[2]=4 | 暂无 |
| 下降 | S(2)调用S(1) | 再加a[1]=-1 | 暂无 |
| 下降 | S(1)调用S(0) | 再加a[0]=2 | 暂无 |
| 基例 | S(0) | 无 | 0 |
| 回升 | S(1) | 0+2 | 2 |
| 回升 | S(2) | 2-1 | 1 |
| 回升 | S(3) | 1+4 | 5 |

**调用栈帧**保存某次调用所需的参数、局部状态和返回位置等信息。语言保证调用语义，具体编译器可能优化实现；教学中的栈帧模型用于解释“各次调用互不混淆”。不要假设C一定做尾调用优化。

二叉树递归只是把一条递归链换成两个子问题。当前根的左子树返回后，还得保留当前根以便进入右子树；这就是普通遍历中栈空间与高度相关的原因。

## 三、用归纳法证明递归，另用度量证明终止

对前n项求和：基例n=0符合空和定义。假设n-1项返回正确，则加上未计入的第n项便得到前n项之和。注意假设只用于更小规模；不能假设“当前函数本来就正确”再推出它正确。

终止另证：度量取非负整数n，每次递归减少1，最终到0。更一般地，递归重建树可取区间长度，链表递归可取剩余结点数。若结构含环，沿next走不一定减少“剩余未访问结点”，原证明失效。

**存在基例不等于一定能到达基例。** 例如以n=0为基例，却不断递归n+1，就没有下降度量。程序可能在到达数学意义的终点之前因栈或整数范围耗尽而失败；算法证明与资源边界都要写。

## 四、循环不变量是“对执行次数做归纳”

把求和改为循环，令i表示已处理项数，total表示这些项之和。不变量为：

$$
0\le i\le n,\qquad total=\sum_{j=0}^{i-1}a_j.
$$

证明必须按这四步走：

1. **初始化**：i=0、total=0，空和成立。
2. **保持**：循环条件i<n保证a[i]可读；把a[i]加入total后，i增加1，不变量仍成立。
3. **终止**：非负整数n-i每轮减少1。
4. **推出目标**：退出时i不小于n，与i不大于n合并得i=n，代入不变量得到所需总和。

不变量不是“最后数组有序”这种只在结束时才成立的愿望，而是每轮约定位置都成立的事实。描述位置也很重要：在total更新后、i更新前，旧公式暂时不适用；循环边界处成立就足以支持这份证明。

## 五、完整C程序：三种求和和边界查找

### 先把程序签名中的符号读出来

`long long sum_recursive(const int *a, size_t n)`分成三部分：long long说明返回一个较宽的整数结果；a保存首个元素的地址，const表示通过a只读取元素；n是要处理的元素数。size_t是用于大小/下标的无符号整数类型，不是函数名，也不会自动检查n是否合法。

`a[n-1]`指第n项，因为数组下标从0开始；`n==0`必须先返回，才能避免零减一的无符号回绕。函数返回一个和，不修改调用者保存的a和n，也不在数组里另写结果。

`sum_divide(a,lo,hi)`则处理左闭右开区间：包含lo，不包含hi。lo=2、hi=5代表下标2、3、4，共3项，长度hi-lo；lo=hi表示空段，长度1时直接取a[lo]。只有长度至少2才继续拆分，否则可能拆出与自身同样大小的子问题。

### 把分治求和的暂停点写出来

取a=[2,-1,4,0]，调用sum_divide(a,0,4)。mid=2，先计算左半[0,2)，再计算右半[2,4)，最后相加。每个调用里的lo、hi、mid是它自己的局部变量，不共享一个全局mid。

| 当前调用 | 左结果来自 | 右结果来自 | 返回值 |
| --- | --- | --- | --- |
| [0,2) | [0,1)返回2 | [1,2)返回-1 | 1 |
| [2,4) | [2,3)返回4 | [3,4)返回0 | 4 |
| [0,4) | 左半返回1 | 右半返回4 | 5 |

最外层的left先得到1，即使随后去计算右半，它仍留在最外层调用状态里，不会被内层也叫left的变量覆盖。代码用两条赋值语句明确先左后右，再return left+right；你不必推测复杂表达式中两个函数调用的求值顺序。

### assert是在测试什么，不是在完成数学证明

`assert(sum_loop(a,n)==prefixes[n])`先算出结果，再检查是否等于事先列好的答案；失败会终止测试，成功继续下一项。prefixes是数组前0项、前1项……的预期和，长度比a多1正是因为包含空前缀。

这是有限样例检查；上面的归纳证明负责说明所有满足前提的输入为什么成立。若程序误用了另一个下标，正确的数学证明也救不了实现，所以两者都需要。不要把puts打印的“passed”当成证明文本，它只表明这一轮断言没有失败。

三种求和分别展示线性递归、平衡分治、迭代。它们解决同一个问题，但调用栈不同。`lower_bound_int`保留第六讲的半开元素区间，用来练习另一种不变量。

为把注意力放在证明而不是溢出上，本例接口约定n≤1024且每项在[-100,100]内，总和绝对值不超过102400，`long long`足够。递归函数本身不扫描检查这个约定；对不可信输入应先做边界校验。n=0允许a为NULL，因为不会访问元素。

```c
#include <assert.h>
#include <stddef.h>
#include <stdio.h>

long long sum_recursive(const int *a, size_t n) {
    if (n == 0) return 0;
    return sum_recursive(a, n - 1) + a[n - 1];
}

/* [lo, hi) is a valid subrange of the input. */
long long sum_divide(const int *a, size_t lo, size_t hi) {
    if (lo == hi) return 0;
    if (hi - lo == 1) return a[lo];
    size_t mid = lo + (hi - lo) / 2;
    long long left = sum_divide(a, lo, mid);
    long long right = sum_divide(a, mid, hi);
    return left + right;
}

long long sum_loop(const int *a, size_t n) {
    long long total = 0;
    for (size_t i = 0; i < n; ++i) total += a[i];
    return total;
}

size_t lower_bound_int(const int *a, size_t n, int key) {
    size_t lo = 0, hi = n;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] < key) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}

int main(void) {
    const int a[] = {2, -1, 4, 0, -5};
    const long long prefixes[] = {0, 2, 1, 5, 5, 0};
    for (size_t n = 0; n <= 5; ++n) {
        assert(sum_recursive(a, n) == prefixes[n]);
        assert(sum_divide(a, 0, n) == prefixes[n]);
        assert(sum_loop(a, n) == prefixes[n]);
    }
    assert(sum_recursive(NULL, 0) == 0);
    assert(sum_divide(NULL, 0, 0) == 0);
    assert(sum_loop(NULL, 0) == 0);
    const int sorted[] = {1, 2, 2, 5};
    const int keys[] = {0, 1, 2, 3, 5, 6};
    const size_t positions[] = {0, 0, 1, 3, 3, 4};
    for (size_t i = 0; i < 6; ++i)
        assert(lower_bound_int(sorted, 4, keys[i]) == positions[i]);
    assert(lower_bound_int(NULL, 0, 7) == 0);
    puts("proof bridge tests passed");
    return 0;
}
```

读代码时先注意 `size_t` 是无符号的大小类型。`n-1`写在n=0返回之后，避免从0减1变成很大的数；`hi-lo`依赖lo≤hi的不变量。语言细节和数学前提在这里直接相接。

循环求和没有“神奇地省掉计算”，只是把待做的加法改为即时累积，不再保留n层未完成调用。分治求和把数据分成两半，每次调用只保留少数状态，深度降到对数级，但仍必须读取所有元素。

## 六、递归树上的时间与空间不能混算

| 实现 | 时间 | 辅助空间 | 原因 |
| --- | --- | --- | --- |
| 线性递归求和 | Θ(n) | O(n) | n层待返回调用 |
| 平衡分治求和 | Θ(n) | O(log n)，n≥2 | 总调用数线性，同一时刻仅一条调用路径及其祖先 |
| 循环求和 | Θ(n) | O(1) | 只维护下标与累加器 |
| 数组lower_bound | O(log(n+1)) | O(1) | 每轮缩小候选区间 |

分治的全部递归调用不是同时压在栈里。左半完成后返回，再处理右半；所以不能拿总调用数当空间。相反，也不能因为高度log n就说时间也是log n：整个递归树各结点都要执行。

数学中的整数加法没有上限，C的有符号整数加法可能溢出；数学中的递归定义存在，不保证操作系统给无限栈。复杂度分析研究规模增长，代码还需明确可处理的实际规模。

## 七、证明、测试与调试各自负责什么

证明说明在明确前提下对所有合法输入成立；测试检查具体实现是否真的符合思路，尤其能发现下标、符号和边界写错。二者互补。上面的断言不是完整证明，前文证明也不能自动证明你键盘打出的每个字符正确。

建议每次调试记录四列：语句、执行前状态、执行后状态、被破坏的不变量。不要直接记“运行崩了”；先定位最早不成立的条件。释放后使用常在出问题那一句之前就已形成悬空指针。

## 八、自编练习与完整思路

**1. 有序数组找key，遇相等立即返回，为什么不能直接用来找首次出现？** 相等只说明当前是一个答案；左边仍可能有相等值。首次出现算法要保留这个候选并继续向左缩小边界。

**2. 递归求树高，为什么不能返回左右高度之和？** 高度对应一条从根向下的路径，不能同时走左右两边。求结点总数才把两个子树规模相加；后置条件不同，合成运算不同。

**3. 求和循环每轮都使i增加，是否就一定正确？** 只能帮助证明终止，还必须证明total确实累加了对应元素。如果把a[i]写成a[0]，它照样终止但结果一般错误。

**4. 二分每步都“看中间”，为什么仍可能死循环？** 例如lo=mid而mid=lo，区间没有缩小。检查长度hi-lo是否严格下降，比盯着变量名更可靠。

**5. 分治求和分配左右数组副本，还能直接用上表空间结论吗？** 不能。上表只传下标、不复制输入。新实现要额外统计副本的分配与生命周期，可能增加空间和复制时间。
