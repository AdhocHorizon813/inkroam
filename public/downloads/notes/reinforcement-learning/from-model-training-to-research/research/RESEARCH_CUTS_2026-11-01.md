# 面向论文产出的切口筛选

日期：2026-11-01。范围：Reasoning RL / RLVR，兼顾数学证明与有限计算资源。**本文件提出候选研究任务，没有认证任何方向无人研究或保证发表。**

## 1. 结论与排序

建议首攻 **P1：带噪审计下，有限 GRPO 组更新的偏差—方差—查询成本折中**。P2 可作为后续主线；P3 保留为 A 的理论备选。原 B 暂降优先级。

| 排序 | 精确研究问题 | 可能形成的论文核心 | 当前判断 |
|---|---|---|---|
| P1 | 审计本身会出错时，有限组的归一化/裁剪更新值得纠正到多精确？ | 明确模型中的风险上下界、达到该界的正则化或查询算法 | 最适合先做数学和 CPU 验证；已有非常近的无噪声审计手稿，必须处理真实新增困难 |
| P2 | 策略依赖同一批审计标签反复更新后，证书何时失效、何时必须补充新标签？ | 同时覆盖自适应参数的保证、基于覆盖/漂移的刷新规则及必要成本 | 应用意义强，理论难；简单 importance weighting 或时间并集界不够 |
| P3 | 生成 rollout 和复核标签分别收费时，识别可靠方向的最优总成本是多少？ | 共享标签反馈下的实例相关复杂度、联合采样/审计分配 | 最贴近原 A，但与主动推断、实验设计和可行性检验重合风险高 |
| P4 | RL 中如何在预算内判断低秩子空间变化来自真实漂移还是估计噪声，并决定刷新？ | 有限样本刷新准则与含校准成本的性能保证 | 作为 B 的收缩备选；普通噪声感知 SVD、子空间跟踪本身已不够新 |

这些排序是基于目前检索的研究判断，不是客观的接收概率。

## 2. 本轮发现的直接先例改变了什么

### 2.1 有限组审计复杂度已有公开手稿

[The Audit Complexity of Group-Relative Policy Updates](https://github.com/Bubu631/agent-audit-complexity) 已研究固定完整标签组的 GRPO surrogate、Boolean query degree、硬审计上限及期望预算下的随机补全。其模型中参考查询揭示确定真值，重复查询不提供新信息。

本轮通过 GitHub 只读连接器读取并固定 commit `c643fd0326fd49061bc7021f08f042bbc0003fa9`，核读模型、主定理与相应 TeX 证明；快照见 [来源记录](../sources/notes/agent_audit_complexity_c643fd0/PROVENANCE.md)。没有复现其全部实验，也没有确认会议发表状态。

因此以下均不能作为本项目的新贡献：有限组归一化不保留逐项 reward correction 的无偏性；用 Boolean degree 给精确无偏审计深度下界；在期望预算下做 randomized telescoping；单独对 advantage 正负部分校正以保持固定参数的 clipped surrogate。

## 3. P1：带噪审计下，纠正整组更新的最优折中

### 问题定义

先冻结一组已生成响应、score、policy ratio。真实二元标签向量为 `r∈{0,1}^K`，目标是完整真值下的明确有限组更新 `F(r)`，而不是直接假定它等于真实正确率梯度。第一版取不带 clipping 的组归一化线性组合，随后才扩到固定参数的裁剪系数。

复核返回独立翻转率 η 已知的标签。必须分别研究：每个响应最多审计一次；允许付费重复独立复核；每次最多 b 次查询的硬预算；只限制期望查询数。这些不是同一个模型。

可写成以下研究目标：

\[
\mathcal R_B(F,\eta)=\inf_{\mathcal A:\sup_r\mathbb E_r[\mathrm{cost}(\mathcal A)]\le B}
\sup_{r\in\{0,1\}^K}\mathbb E_r[(\widehat F-F(r))^2].
\]

这是待求的风险，不是本轮已经得到的定理。还需约束 score 的范数及已知侧信息，明确哪些 r 在条件化后仍可行。

### 要解决的新困难

无噪声的精确审计深度已经有先例；二元线性奖励噪声反演也已有先例。候选贡献应是两者交互导致的**有限预算近似风险**：何时精确无偏的代价太高，何时允许小偏差能有严格可量化的改进，什么查询规则达到相应下界。

Boolean noise operator 的反演、Fourier 低阶截断、正则化逆问题本身都是标准工具；[population recovery](https://theoryofcomputing.org/articles/v016a006/v016a006.pdf) 也是必须比较的跨领域近邻。仅把 Fourier 系数乘以噪声放大因子，不能构成论文核心。

### 本轮已做的机制检查

对单个标准化 advantage，枚举全部二元标签组并反演独立翻转通道；常数组设 advantage=0。这里采用 population std、无 epsilon、每个响应一个带噪标签。下表是均匀标签配置下“无偏估计器二阶矩 / 真实目标二阶矩”，不是训练效果，也不是所有标签分布下的方差比：

| 组大小 K | η=0.2 | η=0.3 |
|---:|---:|---:|
| 4 | 2.873 | 7.470 |
| 8 | 2.994 | 13.537 |
| 12 | 2.936 | 40.834 |
| 16 | 2.873 | 226.178 |

共 15 个设置；条件期望反演的最大数值残差小于 `1.6e−15`。完整 [脚本](tools/probe_group_noise_spectrum.py) 与 [结果](results/group_noise_spectrum.json) 已保存。

两个事实对选题有用：高噪声时高阶相互作用可能非常昂贵；η=0.2 的这些数值并不随 K 明显增长。不能仅由通道的 condition number 推导所有任务的方差爆炸。

另一个反例式提醒：K=16、η=0.3 时，三阶截断在均匀标签配置下的平均平方偏差约 `9.90e−5`，但最坏标签配置下的绝对偏差约 `1.05`。平均指标好并不支持“所有组都可靠”。

### 最小论文贡献包

1. 在明确的一次审计或重复审计模型中，得到目标 F 专属且非平凡的近似风险下界。
2. 给出计算可行的估计/查询算法，并证明匹配或有明确差距的上界；所有额外校准成本计入。
3. 证明什么时候偏差约束足以保持一个实际方向的符号/裕量，而不是从估计 MSE 直接跳到训练收敛。
4. 机制实验后，再检验一个小模型任务；不能用 CPU 枚举结果代替语言模型收益。

强基线至少包括：不校正、线性噪声校正配合不做组内 std 的目标、完整组纠正、同预算随机整组审计、已有无噪声序贯补全的合理扩展。应允许简单目标胜过“纠正原目标”。

**止损条件：**新增证明只是标准噪声反演；下界针对强得不必要的精确恢复要求，放松后困难消失；方法在所有实用设置都被取消 std 的简单目标支配；依赖不符合目标应用的独立复核假设。

## 4. P2：策略自适应更新下的审计复用与刷新

### 问题定义

审计标签的真值不因策略改变而失效，但它在新策略梯度中的权重和所覆盖的响应范围会变。同一带噪标签反复使用，也不会变成多个独立标签。若策略由这批审计结果训练得到，固定策略的无偏性或置信区间不能直接用于该随机策略。

候选问题是：在有界 density ratio、score 正则性及受限参数类下，能否复用一批标签认证多个数据依赖更新，并只在证书不足时补充审计？

固定审计数据采自 `π₀` 时，`wθ=πθ/π₀` 加权是标准起点；新难点应落在自适应 θ、数据复用、score 的参数变化以及刷新总成本。KL 小本身不足以控制逐点比值或无界 score。

### 可能的贡献

- 在一个低维策略类中给出同时对 θ 和方向有效的认证，或给出稳定性条件下更便宜的替代。
- 建立“缓存标签 + 新审计”的刷新机制，并给出依赖覆盖退化/参数复杂度/累计变化的成本保证。
- 给出缺少覆盖时任何缓存方法都必须采新数据的下界。

这是待研究结果。不能把普通 uniform convergence、holdout reuse 或 OPE confidence sequence 换名当贡献；它们是必比基线。第一版可以固定候选策略类，避免直接分析整个 Transformer 参数空间。

### 起步验证与止损

用可枚举 contextual bandit 让策略反复根据同一审计批次更新，比较：每步新审计、固定缓存、独立保留集、简单样本拆分、候选刷新规则。检查的是错误认证率和新增标签成本，并同时报告实际正确率/错误通过率。

若相关定理只是已有 OPE/自适应推断的直接推论，或合法保证所需新标签数几乎等于每步重采样，则停止把该版本作为主线。相较 P1，这条路的理论门槛更高。

## 5. P3：生成与复核双成本的可靠方向识别

### 问题定义

固定策略下可先生成 N 个响应，观察 cheap verifier 与 score，再选择 M 个复核。总费用按 `c_gen N + c_audit M` 计，而不是只报 M。目标是找到使 `g_Cᵀd>0` 且 `−g_Hᵀd>0` 的方向，或在预算内返回无法认证。

同一个标签同时更新所有候选方向的信息，不能把 K 个方向简单当作互相独立的臂。原 A 的两个估计向量也相关：在弱检查通过的样本上，正确率与“负错误通过率”的复核噪声具有共享分量。

### 可能的贡献

最小模型可取有限特征/响应类别、已知复核噪声、有限候选方向。需要建立依赖实际可观测设计和决策裕量的复杂度，再决定何时应继续生成，何时应审计已有响应。

这与 [线性可行性检验](https://proceedings.mlr.press/v235/gangrade24a.html)、[transductive linear bandits](https://arxiv.org/abs/1906.08399)、主动统计推断、最优专家 annotation 都很近。必须尝试形式化归约：直接观测方向导数的 oracle 与“先见响应、后买标签”的 oracle 有何严格区别，是否只差已知成本参数。

**止损条件：**最优分配退化为现成 Neyman allocation；上下界仅是标准实验设计的改写；错误地区分了实际上等价的 oracle；只把 rollout 上界重新命名为 audit 上界。

## 6. P4：B 的可保留版本与暂缓理由

GRAIL、GSLoRA、GoLore 以及近期子空间不可识别性工作使一般性的“考虑梯度噪声后选 SVD 子空间”缺乏足够新意。不能继续把这些作为 B 的空白。

可保留的较窄问题：在固定参数校准分布下，用独立组区分估计不稳定与真实策略漂移，并以净更新收益而非子空间角度为目标决定刷新。刷新应计入校准 rollout、谱计算和优化器状态转换成本。

先读 GoLore、No Subspace to Track、SubTrack、LDAdam，再决定是否值得做。换成 RL 实验场景不自动产生新理论。当前不建议它与 P1 同时投入实现。

## 7. 推荐执行顺序

第一关：为 P1 固定一个精确模型，写出已有无噪声审计定理和标准噪声反演能直接推出的全部结论；这些都列为背景。

第二关：找出真正剩下的风险/预算问题。先在 K≤16 的完全可枚举实例上寻找上下界与算法的差距，尤其保留低噪声、稀疏正确、退化组和方法失效的设置。本轮枚举只是选题探针，不是完成新颖性核查后的正式算法实验。

第三关：若只剩标准工具的直接组合，转 P2 或 P3；若出现能被完整证明的新增结构，再写算法并开展匹配预算的机制实验。只有进入这一步后才考虑小语言模型训练与实验室 GPU。

第一篇论文应围绕一个可检验的主张组织。希望得到的结果是一个明确算法加一个实质理论保证，或一个尖锐边界加达到边界的方法；目前尚未完成这一成果。
